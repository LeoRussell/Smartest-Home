# Gateway: запуск, данные и обслуживание

Gateway — Python-сервер WebSocket для устройств и браузеров. Он проверяет
Schema, хранит данные в SQLite, доставляет команды и исполняет сценарии.
HTTP-файлы интерфейса раздаются отдельно. Общая инструкция запуска находится
в [главном README](../README.md#запуск-gateway).

## Файлы и обязанности

| Путь | Назначение |
| --- | --- |
| `main.py` | Запуск сервера, протокол, доступ устройств, SQLite, очередь команд, интерпретатор автоматизаций, резервные копии |
| `device_configuration.py` | Реестр универсальных драйверов, проверка аппаратной конфигурации, построение логической Schema |
| `requirements.txt` | Зависимости сервера: `websockets>=15,<18` |
| `tests/` | Проверки Schema, конфигурации, событий, связи, диагностики, автоматизаций и консоли с временными БД |
| `gateway.db` | Рабочая база по умолчанию; создаётся, если её нет |
| `schemas/` | JSON-экспорты аппаратных конфигураций универсальных устройств вместе с принятой Schema |
| `backups/` | Снимки SQLite, создаваемые Gateway |

`schemas/` и `backups/` создаются рядом с выбранным файлом БД. При смене пути
базы меняются и эти каталоги. Экспорты Schema не заменяют полную резервную
копию: в них нет журнала, разрешений, очереди команд и сценариев.

## Параметры запуска

| Переменная окружения | Значение по умолчанию | Смысл |
| --- | --- | --- |
| `GATEWAY_HOST` | `0.0.0.0` | Интерфейсы, на которых сервер принимает соединения |
| `GATEWAY_PORT` | `8765` | Порт WebSocket и HTTP-скачивания копий/экспортов |
| `GATEWAY_DB_PATH` | `gateway/gateway.db` в репозитории | Файл SQLite |

Для отдельного тестового экземпляра из корня репозитория в новом окне PowerShell:

```powershell
$env:GATEWAY_DB_PATH = Join-Path $env:TEMP 'smartest-home-test/gateway.db'
.\.venv\Scripts\python.exe gateway\main.py
```

Если по этому пути уже есть база, сервер откроет её. Чтобы получить чистое
окружение, выбери новый путь. Второй сервер на том же IP и порту одновременно
не запустится. Относительный путь `GATEWAY_DB_PATH` считается от текущего
рабочего каталога; для службы удобнее абсолютный путь.

Браузер и ESP32 сейчас используют порт `8765` в своём коде. При изменении
порта сервера измени URL в `web/app.js` и константы `GATEWAY_PORT` в
`esp32/universal/src/main.cpp` и `esp32/examples/led/src/main.cpp`.

## Подключение и актуальность данных

1. ESP32 отправляет `hello` с исходным ID, Schema и версиями.
2. Gateway запрашивает решение для неизвестного устройства. Решение можно
   запомнить; отклонённое навсегда устройство можно разблокировать.
3. Для изменённой Schema Gateway предлагает принять её или оставить прежнюю.
   Сравнивается содержимое, даже если номер версии не изменился.
4. После разрешения Gateway отправляет `hello_ack`. Устройство начинает
   отправлять состояние. Универсальный профиль дополнительно синхронизирует
   аппаратную конфигурацию.

Разрешение по ID не удостоверяет физическую плату: другое устройство может
представиться тем же ID. Сейчас сервер предназначен для доверенной LAN;
встроенных TLS и авторизации браузеров нет.

Состояние «Подключено» относится к соединению WebSocket. Показания имеют
отдельную актуальность: автоматизация читает параметр только из текущей
сессии и при возрасте принятого значения не более 45 секунд. Новый отчёт по
другому параметру, пустой heartbeat или Pong не освежает старое значение.

Сервер посылает штатные WebSocket Ping каждые 20 секунд и ждёт Pong до 20
секунд. Watchdog также проверяет Ping/Pong при длительном отсутствии
прикладных сообщений; сам факт отсутствия показаний не закрывает живую связь.
При реальном разрыве в консоли выводятся код, причина и возраст последних
сообщений и показаний.

## Команды и консоль

В интерактивном терминале доступны:

| Команда | Действие |
| --- | --- |
| `devices` | Известные устройства, их состояние и параметры |
| `status` | Число подключённых устройств и браузеров |
| `use esp32-01` | Выбрать устройство для следующих команд |
| `schema` или `schema esp32-01` | Принятая Schema |
| `set led true` | Записать JSON-значение в объявленный параметр |
| `call identify` | Вызвать объявленное действие без аргументов |
| `call calibrate {"offset": 0.5}` | Вызвать действие с JSON-аргументами, если оно объявлено |
| `events` | Последние видимые события |
| `history` | Сохранённые устройства |
| `exit` | Завершить сервер |

Примеры `led`, `identify`, `calibrate` работают только при наличии этих ID в
Schema выбранного устройства. Вводимые значения — JSON: `true`, `42`,
`"night"`, а не Python `True` или некавыченная строка.

Без интерактивного stdin Gateway работает как служба и не ждёт команд.
Установка systemd описана в [главном README](../README.md#linux-и-автозапуск).

Команда сохраняется в SQLite до отправки. Подтверждение ожидается 5 секунд.
Повторы с тем же `command_id` допустимы только при объявленной поддержке
`command_dedup`; детали и ограничение гарантии выполнения описаны в
[руководстве прошивки](../docs/ADVANCED_FIRMWARE.md#подтверждения-и-повторная-доставка).

## Данные и резервные копии

В SQLite хранятся устройства и псевдонимы ID, принятые Schema и их снимки,
аппаратные конфигурации и их история, значения параметров, разрешения и
блокировки, предпочтения вида контролов, очередь команд, события, сценарии,
история запусков и накопленное время работы Gateway.

Язык, часовой пояс, расположение меню, избранное, сортировка карточек и
прочитанные уведомления хранятся в `localStorage` браузера. Резервная копия БД
не переносит эти предпочтения и Wi-Fi-пароли из `secrets.h`.

В «Настройки → Резервные копии»:

1. Создай копию. Gateway использует SQLite backup API и проверяет целостность
   снимка; останавливать сервер для создания копии не нужно.
2. Скачай файл `.sqlite3`, если нужна копия вне компьютера Gateway.
3. Для отката выбери восстановление снимка из списка и подтверди действие.

Каталог хранит до 20 снимков; при создании следующего удаляются самые старые.
Перед восстановлением создаётся страховочный снимок текущей БД. Сценарии
останавливаются, текущие подключения ESP32 закрываются, после восстановления
устройства могут подключиться снова. Сценарии не продолжаются с середины
старой паузы. Принятая конфигурация Gateway затем синхронизируется с платой.

Загрузка произвольного файла копии из браузера сейчас не реализована.
Чтобы вернуть ранее скачанный файл, положи его с исходным именем
`gateway-YYYYMMDD-HHMMSS-<32 hex>.sqlite3` в каталог `backups/` рядом с текущей
БД и обнови список. Gateway проверит формат и целостность перед восстановлением.
Копия включает все записи БД; отдельные файлы экспортов заново синхронизируются
из восстановленных данных.

При старте сервер сам создаёт отсутствующие таблицы и добавляет необходимые
колонки. Редактировать SQL для обычного обновления проекта не требуется.
Сохранённые ранее рабочие данные не следует заменять пустой БД.

В текущем репозитории `gateway.db` и некоторые JSON в `schemas/` уже
отслеживаются Git. Каталог `backups/` исключён из Git. Перед коммитом проверяй
`git status`: рабочая БД содержит историю конкретной установки, а не только
структуру таблиц.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Страница открывается, Gateway отключён | Запущен ли Python-сервер, доступен ли TCP 8765, совпадает ли компьютер HTTP-сервера и Gateway |
| Плата не подключается | LAN IP в `secrets.h`, Wi-Fi, порт, брандмауэр, решение о доступе в браузере |
| Две платы постоянно вытесняют друг друга | У каждой платы должен быть уникальный ID; второе соединение с тем же ID заменяет первое |
| Периодические отключения | Сопоставить `[CLOSE]` в Gateway с `[NET]`/`[BOOT]` в Serial; подробнее в [диагностике ESP32](../docs/UNIVERSAL_FIRMWARE.md#связь-и-диагностика-переподключений) |
| Устройство подключено, сценарий не читает параметр | Нужен свежий `state` с этим параметром после `hello_ack`; проверить Schema и статус аппаратной конфигурации |
| Новая конфигурация сохранена, карточка старая | Дождаться ACK ESP32; проверить сохранённую и подтверждённую версии, затем «Повторить сохранённую» |
| Изменение интерфейса не видно | Обновить страницу через Ctrl+F5; проверить консоль браузера |

Проверки запускаются из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s gateway -p "test_*.py"
```

Они используют временные базы и тестовые соединения. Электрическую схему,
радиосвязь и питание проверяют на реальной плате; это не заменяется тестами
протокола.
