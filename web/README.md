# Веб-интерфейс

Статическое приложение с оформлением в стиле Windows 98. Для работы нужны
браузер, HTTP-сервер и запущенный Gateway. Node.js и сборщик не используются.

Для совместного запуска шлюза и страницы из корня репозитория:

```powershell
py run.py
```

Для запуска только страницы при уже работающем Gateway:

```powershell
py -m http.server 8080 --directory web
```

Открой `http://localhost:8080` или ссылку `Local network`, которую выводит
`run.py`: `http://<LAN-IP-компьютера>:8080`. Ссылка подходит для другого
компьютера или телефона в той же сети. [Доступ по LAN](../docs/LAN_ACCESS.md).
Gateway доступен на том же узле: `run.py` сообщает браузеру фактический порт,
а отдельный статический сервер использует `8765`. Другой IP или порт
задаётся через «Настройки» → «Подключение к Gateway». Этот адрес определяет
WebSocket и скачивание резервных копий/Schema. После изменения страница
перезагружается; уведомления и локальные черновики изолированы по адресу шлюза.
Адреса прослушивания `0.0.0.0` и `[::]` не сохраняются как адрес подключения;
старое такое значение сбрасывается автоматически. На том же компьютере можно
использовать `ws://localhost:8765`, на другом — доступный IP компьютера с Gateway.
Ожидание открытия WebSocket ограничено 10 секундами. При недоступности адреса
появляется пояснение с выбранным и автоматическим URL; попытки повторяются
с тем же адресом. После восстановления связи это сообщение убирается.
Запуск через `file://`
не является штатным способом работы.

## Что доступно пользователю

Значок **i** рядом с заголовком или полем открывает дополнительное пояснение
при наведении, фокусе с клавиатуры или нажатии. Нажатие закрепляет подсказку;
повторное нажатие, клик снаружи или Escape закрывают её. Escape сначала
закрывает пояснение, сохраняя открытое окно и его черновик. Описания компонентов,
драйверов и сложных метрик используют этот механизм; ошибки, статусы и
предупреждения о несохранённых изменениях остаются видимыми.

- **Обзор:** кнопка «Настроить» позволяет выбрать до 24 параметров, действий
  устройства и ручных сценариев. Логическими параметрами можно управлять
  кнопкой следующего действия: зелёной «Вкл» или красной «Выкл»;
  числовыми и перечислениями — через поле или список.
  Параметры `read_only` показывают значение без управления.
  Команды выбора режимов из `schema.modes` объединены в одну плитку устройства
  со списком и кнопкой «Применить». Пара команд включения и выключения режима
  показывается одним переключателем с названием режима, например «Мигание».
  Его состояние берётся из свежей телеметрии `status_parameter` / `status_value`;
  без известного состояния переключатель недоступен. При ожидании результата
  команды управление режимами устройства блокируется до подтверждения.
  Старые плитки отдельных команд объединяются автоматически с сохранением
  первого места группы в раскладке. Действия с аргументами сохраняют обычную форму.
  Графики за минуту, час, сутки и неделю доступны в секции «История показаний»
  и по значку графика справа от параметра устройства; есть таблица и CSV.
  Нажатие или касание графика выбирает ближайшую точку и показывает её значение
  и время рядом с маркером. Для клавиатуры: Tab к графику, ←/→, Home/End.
  Исходный период — минута для boolean и час для числовых параметров;
  явно выбранный период сохраняется в браузере и используется для следующих
  графиков. Таблица и CSV содержат показанные точки с min/max и числом замеров:
  на длинном периоде одна точка может объединять несколько исходных значений.
  Объяснение линии и объединения замеров скрыто под ⓘ рядом с заголовком истории.
  Параметры с `history: false` или `history: {"enabled": false}` не появляются
  в выборе графиков и не имеют кнопки графика. Сам параметр и его управление
  остаются доступны на карточке и в настройке состава обзора.
  В обзоре значок графика находится вверху плитки рядом с ручкой перемещения.
  Плитки перетаскиваются за специальную ручку; в «Настроить» порядок меняется
  кнопками ↑/↓. Значок и подпись различают устройство, показание, команду
  и ручной сценарий. Изменения в окне настройки применяются после сохранения.
  На плитке сценария «Изменить» открывает сохранённые блоки в редакторе,
  «Тест» — симуляцию с виртуальными значениями без команд устройствам.
  Ниже названия видны время и результат последнего запуска, при ошибке — причина.
  Во время выполнения показывается начало текущего запуска; при потере Gateway
  его итог уточняется после подключения. Редактирование доступно и без связи.
  [Как собирается история](../docs/HISTORY.md).
- **Устройства:** поиск и фильтры, избранное и сортировка, смена имени/ID,
  параметры и действия из Schema, выбор авторских режимов, настройка
  универсальной платы, история Schema и раскрываемый список блокировок.
  Также доступны группы, общее выключение для группы/всех и диагностика
  Wi-Fi, времени работы и последнего разрыва. [Инструкция](../docs/DEVICE_GROUPS.md).
  «История соединений» открывается значком списка справа в диагностике карточки или через
  шестерёнку → «Связь и подключения». В компактном виде блок находится внутри
  «Сведения об устройстве». В окне видны сессии, причины закрытия и измерения
  связи; незаполненные метрики означают отсутствие наблюдения.
  «Скачать отчёт» выгружает загруженные сессии в JSON, в том числе при потере связи.
  [Как читать историю](../docs/CONNECTIONS.md).
  Быстрые сценарии показывают ручные программы с флажком «Кнопка на странице
  устройств».
  В панели показаны устройства сценария, готовность и результат последнего
  запуска. «Запустить» выполняет программу, «Изменить» открывает её в Blockly,
  а «Все сценарии» переводит к списку автоматизаций.
  В шапке карточки звезда меняет избранное, шестерёнка открывает настройки,
  метка — «Найти устройство», если прошивка объявила эту возможность.
  Кнопка «Schema» у универсальной прошивки открывает конструктор аппаратной
  конфигурации; это отдельное окно от истории принятых Schema.
  Read-only параметры, указанные как `modes.*.status_parameter`, отдельно
  в карточке не дублируются: их состояние показано в разделе выбора режима.
  Они остаются доступны сценариям; управляемые параметры и фактический выход
  светодиода отображаются обычным образом.
  В окне шестерёнки сверху редактируются имя и ID, ниже расположены группа,
  общее выключение, связь и история Schema. Для смены ID устройство нужно
  отключить; отображаемое имя можно сохранять и при подключённом устройстве.
  Название группы видно и на основной карточке.
  На широком экране группа и связь расположены в левой колонке, общее
  выключение — справа; на телефоне блоки идут последовательно. В истории
  соединений пояснение находится в общем нижнем ряду с кнопкой закрытия.
  Ответы сохранения привязаны к конкретному запросу: поздний ответ из закрытого
  окна не сбрасывает новую форму. Изменения, внесённые во время сохранения
  общего выключения, остаются в редакторе; сохранение одной группы не очищает
  черновики остальных. При отсутствии ответа через 20 секунд управление
  возвращается пользователю с предупреждением о неизвестном результате.
  «Проводник устройств» сворачивается нажатием на заголовок; на телефоне он
  изначально свёрнут, чтобы быстрее добраться до управления устройствами.
  Поиск, сортировка, группы и общее выключение находятся внутри него.
  Перед карточками выбираются подробный/компактный вид и список/комнаты.
  Комнаты используют существующие группы. Значок питания в заголовке комнаты
  выполняет назначенные операции всей группы, независимо от поискового фильтра;
  это не отключение питания самой ESP32. Соответствие «выключить» задаётся
  явно в настройках устройства: например, boolean = false или скорость = 0.
  Стрелка возле изменяемого параметра открывает выбор вида элемента управления;
  доступны только варианты, совместимые с его типом, диапазоном и Schema.
- **Автоматизация:** Blockly, проверка без выполнения команд, управление
  сценариями и история запусков. Список сохранённых сценариев расположен
  над Blockly; «Изменить» прокручивает страницу к редактору.
  «Копировать» открывает отдельный несохранённый черновик с новым именем;
  исходный сценарий и его история не изменяются.
  Сообщения о запуске, остановке и изменениях истории показаны над списком
  сценариев; ошибки редактирования остаются возле полей Blockly.
  Во время запуска показываются текущий шаг, ожидание подтверждения команды
  и оставшееся время паузы. В редакторе сохранённого сценария подсвечивается
  выполняемый блок, если черновик соответствует запущенной программе.
  «Тестовый запуск» под Blockly открывает модель черновика, а «Тест» в карточке
  сценария — сохранённой программы. Можно задать виртуальные показания и
  подключения, затем увидеть ветви, команды и виртуальное время пауз.
  Нужна связь с Gateway; реальные ESP32 могут быть отключены. Тест не отправляет
  команды устройствам, не меняет выполняемые сценарии и не сохраняет события
  или историю запусков.
  [Возможности теста](../docs/AUTOMATION.md#тестовый-запуск-без-устройств).
  [Руководство](../docs/AUTOMATION.md).
- **События:** поиск, выбор устройства и типа, подгрузка старой истории,
  CSV и переход `>>` к связанному запуску сценария. Успешные команды
  автоматизации представлены фактическими изменениями состояния.
  Новые записи сохраняют клавиатурный фокус на фильтре или действии выбранного
  события; поиск сохраняет положение курсора. В уведомлениях открытая запись
  также остаётся доступной при поступлении новых сообщений.
  Фильтр «Настройка оборудования» показывает сохранение и применение GPIO/
  драйверов универсальной прошивки, ошибки, таймауты и восстановление конфигурации.
- **Настройки:** язык, часовой пояс, верхнее/боковое меню, важность
  уведомлений, статистика БД, резервные копии и общий срок хранения событий
  (90 дней по умолчанию; `0` — без автоочистки).
  История показаний имеет отдельные настройки записи, интервала и срока
  хранения: по умолчанию 30 секунд и 30 дней, не более 250 000 замеров.

Резервные копии в настройках изначально свёрнуты. Нажатие на заголовок
раскрывает прежние команды создания, скачивания и восстановления. Запрос списка
ожидает ответ до 15 секунд, создание — до 30 секунд, восстановление — до 90 секунд.
Если подтверждения нет, кнопки снова доступны и показывается предупреждение:
операция могла завершиться на Gateway. Автоматического повторения нет; перед
повторным созданием или восстановлением проверьте список и состояние шлюза.
Ответы с идентификатором прежнего запроса не завершают текущую операцию.
В шапке
домик ведёт к устройствам; отдельная панель показывает короткий статус связи
с Gateway и цветной индикатор.

Статус Gateway и колокольчик доступны на всех страницах. Красный счётчик
появляется при непрочитанных уведомлениях; нажатие на запись открывает
связанное устройство, событие или запуск.

CSV событий выгружает загруженные записи, подходящие под текущие фильтры. Для
более старых событий сначала подгрузите нужные страницы. CSV показаний выгружает
точки текущего графика; смените период, чтобы выбрать другой диапазон.
Штатный локальный
запуск использует HTTP и WS; собственного HTTPS/WSS-сервера проект не запускает.

## Где сохраняются настройки

Gateway хранит в SQLite имя и ID, аппаратную конфигурацию, вид каждого
контрола, сценарии, историю, группы, общие команды и срок хранения событий.
История соединений также хранится на Gateway: закрытые сессии — до 90 дней,
не более 1000 на устройство и 10 000 на весь Gateway, независимо от срока
хранения событий. Она начинает накапливаться после обновления сервера;
старые события в сессии не преобразуются. Результат виртуального теста
не добавляется в сохранённую историю запусков.
Выбор «Список» строится по типу и допустимым
значениям Schema: пользователь не задаёт новые значения одним изменением вида.

Возраст показания отслеживается отдельно для каждого параметра. Новые данные
выхода или пустой heartbeat не делают старую температуру DS18B20 свежей.
Карточка и обзор показывают «Устарело» после превышения порога Gateway
(по умолчанию 45 секунд), а при отсутствии измерения текущего подключения —
«Нет свежих показаний». Возраст увеличивается и без новых сообщений.
При этом последнее известное значение остаётся видимым; статус «Подключено»
не означает, что все датчики обновляются. Старые Gateway, которые не передают
возраст отдельных параметров, сохраняют прежнее отображение.

Браузер хранит язык, часовой пояс, расположение меню, избранное, сортировку,
подробный/компактный вид, список/комнаты и свёрнутые комнаты, состав и порядок
плиток обзора, выбранный период графика, показ min/max и прочитанные уведомления
в `localStorage`. Это локальные предпочтения: для них нет кнопки сохранения
на Gateway. Очистка данных сайта
сбросит эти предпочтения, но не БД Gateway. На другом компьютере или другом
origin (`localhost` и LAN IP — разные origin) эти настройки независимы.
Незавершённые блоки и имя сценария автоматически копируются в браузер с задержкой
500 мс; предел копии — 128 КиБ. После перезагрузки над редактором появляются
«Восстановить черновик» и «Удалить локальную копию». Восстановление требует
действия пользователя и не сохраняет сценарий на Gateway. Копии привязаны к
адресу выбранного Gateway; другая вкладка не перезаписывается без предупреждения.
Повреждение данных, переполнение хранилища или слишком большой черновик
показываются явно. Локальную копию и черновик конфигурации не следует считать
резервной копией базы.

## Автоматическая проверка

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe web\tests\browser_smoke.py
```

Проверка запускает локальный HTTP-сервер на свободном порту и изолированный
Chrome/Chromium/Edge с временным профилем. WebSocket заменён тестовым до загрузки
страницы: рабочий Gateway, ESP32 и база не затрагиваются. Проверяются действия,
редактор, выбор точек графика мышью/касанием и клавиатурой, сохранение периода,
параметры с отключённой историей, адреса подключения и 60 вариантов раскладки RU/EN, верхнего/
бокового меню и ширины 1440/375/320. При необходимости укажи браузер через
`--chrome <путь>` или `CHROME_PATH`.
Явно заданный путь имеет приоритет; неверный путь останавливает проверку с
сообщением. CI устанавливает закреплённую версию Chrome for Testing и передаёт
её исполняемый файл через `CHROME_PATH`. Запуск браузера и загрузка интерфейса
имеют отдельные сроки ожидания по 30 секунд с повторными запросами. При сбое
запуска выводятся выбранный файл, каталог временного профиля, `stderr` и файловый
журнал Chrome; при ошибке загрузки страницы — её адрес, состояние и ошибки JavaScript.
На Ubuntu runner переменная `CHROME_DEVEL_SANDBOX` указывает на sandbox-helper
уже установленного Google Chrome. Workflow настраивает для этого файла владельца
root и режим 4755 в одноразовом runner, чтобы Chrome for Testing мог использовать
SUID sandbox при ограничениях AppArmor.
Параметр `--screenshots <каталог>` дополнительно сохраняет снимки новых окон
для компьютера и узкого экрана. Профиль тестового браузера остаётся временным.

## Изменение интерфейса

При первом нажатии Tab появляется ссылка «Перейти к содержимому». Между вкладками
можно перемещаться стрелками (вверх/вниз для бокового меню, влево/вправо для верхнего),
Home и End выбирают первую и последнюю вкладки. На узком экране меню всегда горизонтальное.
Уведомления открываются с клавиатуры через кнопку колокольчика; Escape закрывает уведомления или диалог,
возвращая фокус на кнопку открытия. Системная настройка уменьшения анимации учитывается.

Русские и английские строки находятся в `data-ru`/`data-en` HTML и словарях
JavaScript. Для нового элемента добавляй оба перевода. Карточки и Blockly
строятся по Schema: отдельной логики для параметра `led` быть не должно.

Проверяй цвета текста, активных и отключённых кнопок в диалогах, состояние
фокуса, узкую ширину экрана и обе позиции навигации. Окна, выпадающие списки
и элементы Blockly должны корректно перекрываться при прокрутке.

После изменения скриптов или CSS обнови страницу через Ctrl+F5 и проверь
консоль браузера. Для нового WebSocket-действия обновляй обработчики
`gateway/protocol.py` и `app.js` согласованно; действия групп и настроек
обрабатывает `gateway/device_management.py`. Проверка формы в браузере не
заменяет серверную валидацию. Если меняется протокол состояния/событий,
проверь одновременно журнал, уведомления, фильтры, счётчики и CSV.

Для короткой ручной проверки пройди разрешение устройства, смену Schema,
ручную команду, один сценарий с паузой, сохранение аппаратной конфигурации,
переподключение Gateway и просмотр старой истории. Полный набор проверок —
в [приёмочном плане](../docs/ACCEPTANCE_TESTING.md). Работай с отдельной
тестовой БД, если проверка включает удаление или восстановление данных;
[как её выбрать](../gateway/README.md#параметры-запуска).
