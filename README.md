# Smartest-Home

Локальный IoT Gateway для ESP32 и других устройств с поддерживаемым WebSocket-протоколом. Gateway принимает Schema и телеметрию устройств, сохраняет их в SQLite и предоставляет веб-интерфейс для просмотра параметров и вызова объявленных действий.

## Структура проекта

- `gateway/` — WebSocket-сервер на Python и SQLite база `gateway.db`.
- `web/` — статический интерфейс на HTML, CSS и JavaScript.
- `web/vendor/blockly/` — локальная Blockly 13.4.0 и Russian/English локали; веб-приложению не нужен CDN или сборщик.
- `esp32/` — прошивка Arduino/PlatformIO для ESP32-S3 DevKitC-1 и Adafruit Feather.
- `esp32/universal/` — отдельная универсальная прошивка с настраиваемыми GPIO-драйверами.
- `docs/AUTOMATION.md` — описание сценариев автоматизации и пользовательских режимов устройств.
- `docs/DEVICE_SCHEMA.md` — формат Schema, версий и аппаратной конфигурации.
- `docs/UNIVERSAL_FIRMWARE.md` — загрузка универсальной прошивки, настройка GPIO и ограничения драйверов.
- `docs/ADVANCED_FIRMWARE.md` — подключение общей ESP32-библиотеки и протокол пользовательской прошивки.

Gateway слушает WebSocket на порту `8765`. Веб-файлы раздаются отдельным HTTP-сервером на порту `8080`.

Адрес, порт и путь к базе Gateway можно переопределить переменными `GATEWAY_HOST`, `GATEWAY_PORT` и `GATEWAY_DB_PATH`. Без них используются `0.0.0.0:8765` и `gateway/gateway.db`.

## Запуск Gateway

Из корня репозитория в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r gateway\requirements.txt
.\.venv\Scripts\python.exe gateway\main.py
```

В отдельном окне PowerShell запусти веб-страницу:

```powershell
py -m http.server 8080 --directory web
```

Открой `http://localhost:8080`. Для доступа с другого устройства в локальной сети используй IP компьютера с Gateway вместо `localhost`.

## Настройка ESP32

Скопируй `esp32/include/secrets.example.h` в `esp32/include/secrets.h` и укажи Wi-Fi и IP компьютера, где запущен Gateway. `secrets.h` исключён из Git. Прошивка собирается PlatformIO из каталога `esp32`; профиль по умолчанию — `esp32-s3-devkitc-1`.

Профиль `esp32-s3-devkitc-1` управляет обычным светодиодом на GPIO 48 прямым цифровым сигналом; команда включения держит пин в активном состоянии, а `identify` мигает им пять раз. Это подходит для внешнего светодиода, подключённого к GPIO 48 через токоограничивающий резистор. Адресный RGB-светодиод ESP32-S3 DevKitC-1 требует NeoPixel-протокола: на v1.0 он подключён к GPIO 48, на v1.1 — к GPIO 38. Для адресных индикаторов выбери профиль `esp32-s3-devkitc-1-v1_0-neopixel` или `esp32-s3-devkitc-1-v1_1`. Для Adafruit Feather ESP32-S3 выбери `adafruit_feather_esp32s3`: он управляет красным GPIO-светодиодом на GPIO 13. В Serial выводятся тип драйвера и GPIO. Чтобы прошить плату, из каталога `esp32` запусти `pio run -e esp32-s3-devkitc-1 -t upload`; для остальных плат укажи соответствующий профиль. Serial monitor запускается командой `pio device monitor -e esp32-s3-devkitc-1` на скорости 115200 бод. Пин и драйвер выбираются профилем в `platformio.ini`; для платы без индикатора установи `DEVICE_HAS_IDENTIFY_INDICATOR` в `0`. В Schema доступны `capabilities.built_in_indicator`, `capabilities.identify` и `actions.identify`.

Для подключения нескольких плат задай каждой уникальный `DEVICE_ID` в этом файле перед прошивкой. `DEVICE_NAME` и `DEVICE_MODEL` можно настроить отдельно; имя и состояние каждой платы Gateway хранит по её ID.

Для начальной настройки без написания C++ используй отдельный проект
`esp32/universal`. Он умеет цифровые входы и выходы, ADC и PWM, принимает
конфигурацию от Gateway и сохраняет её между перезапусками. По желанию можно
скачать сгенерированный `device_configuration.generated.h`, положить его в
`esp32/universal/include` и загрузить конфигурацию вместе с прошивкой. Это
необязательно для обычных изменений: Gateway применяет конфигурацию динамически.
ID и имя этой прошивки задаются в `esp32/universal/include/user_config.h`.
Полная инструкция, список разрешённых пинов и ограничения датчиков находятся в
[`docs/UNIVERSAL_FIRMWARE.md`](docs/UNIVERSAL_FIRMWARE.md).

В универсальном конструкторе можно дополнительно назначить GPIO- или
NeoPixel-индикатор для действия «Найти устройство». Для обычного GPIO-светодиода
задаётся активный уровень; для встроенного RGB-индикатора можно выбрать GPIO 38
или 48 и яркость. Драйвер и физическое подключение автоматически не
определяются — укажите их по документации своей платы.

В профиле для продвинутых пользователей сетевой клиент отделён от `main.cpp`.
Schema описывается в `esp32/src/DeviceSchema.cpp`, пользовательские режимы — в
`esp32/src/DeviceModes.cpp`, а основной файл связывает возможности устройства
с командами и телеметрией.

## Schema и база данных

При каждом подключении устройство отправляет ID и Schema в `hello`. Для первого подключения Gateway сохраняет эту Schema. При следующих подключениях он сравнивает её с принятой версией по содержимому, независимо от `schema_version`: если Schema не менялась, соединение продолжается; если изменилась, веб-интерфейс показывает список добавленных, удалённых и изменённых параметров и действий. До решения остаётся активна прежняя Schema, а команды устройства временно блокируются. Принятие сохраняет новую Schema в `devices.schema_json` и версию в `devices.schema_version`. Если оставить текущую Schema, она остаётся активной; при следующем подключении Gateway снова предложит изменение, если оно всё ещё есть.

Последнее состояние параметров хранится отдельно в `devices.state_json`. Действия являются частью Schema, поэтому добавление `identify` не требует отдельной SQLite-колонки.

Управляемый параметр может задавать подсказку `control` внутри собственного описания. Допустимы `toggle` для boolean, `slider` для integer/number с `min` и `max`, `select` для enum и `input` для числовых или текстовых значений. Gateway проверяет совместимость подсказки с типом параметра и его границами. Если `control` не указан, интерфейс автоматически выбирает переключатель для boolean, список для enum, ползунок для числового диапазона и поле ввода в остальных случаях. Подсказка меняет только отображение: тип, доступ и допустимые значения по-прежнему задаются Schema.

Например, Schema лампы объявляет переключатель, а датчик яркости с диапазоном от 0 до 100 — ползунок:

```json
{
  "parameters": {
    "led": {
      "label": "Светодиод",
      "type": "boolean",
      "access": "read_write",
      "control": "toggle"
    },
    "brightness": {
      "label": "Яркость",
      "type": "integer",
      "access": "read_write",
      "min": 0,
      "max": 100,
      "step": 1,
      "control": "slider"
    }
  }
}
```

Когда прошивка меняет Schema, увеличь `schema_version`. Gateway сравнивает содержимое независимо от номера версии и предложит подтвердить изменение; существующая SQLite-схема при этом не меняется.

Устройство без Schema отображается с автоматически выведенными параметрами только для чтения. Управляемые параметры и действия должны быть явно объявлены устройством. Действие может объявить типизированные `arguments`; Gateway проверяет обязательность, тип и ограничения, а браузер строит для них форму.

Например, действие калибровки может принимать числовое смещение и необязательный режим:

```json
{
  "actions": {
    "calibrate": {
      "label": "Калибровка",
      "arguments": {
        "offset": {"label": "Смещение", "type": "number", "min": -5, "max": 5},
        "mode": {
          "label": "Режим",
          "type": "enum",
          "required": false,
          "options": [
            {"label": "Быстро", "value": "fast"},
            {"label": "Точно", "value": "fine"}
          ]
        }
      }
    }
  }
}
```

## Доступ, доставка команд и история Schema

Для неизвестного ID Gateway приостанавливает подключение и показывает запрос в веб-интерфейсе. Без флажка «Запомнить выбор» разрешение или отказ действует только для этой попытки подключения. С флажком разрешение сохраняется для следующих подключений, а отказ добавляет устройство в список постоянных блокировок. Старые устройства, уже записанные в базе до этой функции, сохраняют доступ.

Кнопка «Забыть» отключает устройство и снимает сохранённое разрешение. Запись об устройстве скрывается из рабочего списка; журнал событий и снимки Schema остаются в базе. Следующая попытка снова потребует решения. Постоянную блокировку можно снять в списке заблокированных устройств или кнопкой в событии о постоянном запрете; следующая попытка снова запросит решение.

Gateway записывает команду в SQLite до отправки. Если подтверждение не пришло, он повторно отправляет ту же команду с тем же `command_id`, а после нескольких попыток оставляет её в очереди до следующего подключения. Тестовая прошивка ESP32 объявляет `command_dedup: true`, сохраняет последние 16 ответов в NVS и возвращает сохранённый ответ при повторе ID, чтобы повторная доставка не запускала действие заново. Gateway автоматически повторяет команды только устройствам, объявившим эту поддержку. Для прошивок без неё команда отправляется один раз: если ответ теряется, Gateway фиксирует отсутствие подтверждения и не рискует выполнить действие повторно. Другим прошивкам нужна такая же обработка `command_id`.

Это доставка с повторными попытками и подавлением дублей для совместимой прошивки, но не абсолютная гарантия «ровно один раз»: если питание пропадёт после выполнения действия, но до сохранения ответа в NVS, повтор может выполнить его ещё раз.

Gateway сохраняет принятые снимки Schema. В истории карточки устройства выбранный снимок можно восстановить, пока устройство отключено, или удалить с подтверждением. Удаление влияет только на запись в истории и не меняет текущую Schema устройства. Восстановление меняет принятую Schema в Gateway, но не прошивку устройства; при следующем подключении Gateway сравнит обе версии и запросит решение, если они отличаются.

Веб-интерфейс разделён на страницы устройств, событий и настроек. В настройках можно выбрать верхнее или боковое меню, язык (русский или английский), часовой пояс и фильтр важных уведомлений. Эти предпочтения и отметки о прочитанных событиях хранятся в браузере. Нажатие на уведомление открывает соответствующее событие в журнале.

## Автоматизация

Во вкладке «Автоматизация» используется Blockly. Сценарий можно запускать при изменении параметра, подключении или отключении устройства, а также при старте Gateway. Рабочая область сохраняется вместе с проверенной программой в SQLite. Gateway поддерживает условия и ветвления, установку разрешённых параметров, вызов `actions` с аргументами по Schema и ожидание результата команды. Подробности и пример гистерезиса приведены в [`docs/AUTOMATION.md`](docs/AUTOMATION.md).

## Консоль Gateway

- `devices`, `status` — список устройств и состояние Gateway.
- `use <device_id>` — выбрать устройство.
- `schema [device_id]` — посмотреть сохранённую Schema.
- `set <parameter> <json_value>` — установить объявленный параметр.
- `call <action_id> [json_arguments]` — вызвать объявленное действие; аргументы проверяются по Schema.
- `events`, `history` — посмотреть журнал и сохранённые устройства.
- `exit` — корректно остановить Gateway.

## Linux и автозапуск

В репозитории есть unit-файл `deploy/smartest-home-gateway.service` для `systemd`. Он рассчитан на установку проекта в `/opt/smartest-home`, отдельного системного пользователя `smartest-home` и базы в `/var/lib/smartest-home/gateway.db`.

Сначала склонируй или скопируй репозиторий в `/opt/smartest-home`. Затем создай системного пользователя и каталог базы, передай файлы проекта этому пользователю и установи зависимости:

```sh
sudo useradd --system --user-group --home /opt/smartest-home --shell /usr/sbin/nologin smartest-home
sudo install -d -o smartest-home -g smartest-home /var/lib/smartest-home
sudo chown -R smartest-home:smartest-home /opt/smartest-home
sudo -u smartest-home python3 -m venv /opt/smartest-home/.venv
sudo -u smartest-home /opt/smartest-home/.venv/bin/pip install -r /opt/smartest-home/gateway/requirements.txt
sudo cp /opt/smartest-home/deploy/smartest-home-gateway.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now smartest-home-gateway
```

Проверяй состояние через `systemctl status smartest-home-gateway`, а журналы — через `journalctl -u smartest-home-gateway -f`. В служебном режиме Gateway не ожидает ввода из консоли и остаётся запущенным до остановки systemd. Для веб-интерфейса по-прежнему нужен HTTP-сервер на каталоге `web`; открой только необходимые порты в доверенной локальной сети.
