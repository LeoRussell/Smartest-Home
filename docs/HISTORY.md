# История показаний и графики

Gateway сохраняет измерения параметров отдельно от журнала событий. Запись идёт
на самом шлюзе, даже если браузер закрыт. Она начинается после обновления Gateway:
старые записи событий автоматически не превращаются в измерения.

Синяя линия показывает среднее числовое значение или последнее логическое
состояние в интервале (0 — выключено, 1 — включено). Флажок min/max включает
голубые полосы: минимум и максимум исходных показаний внутри объединённого
интервала. По умолчанию они скрыты; если внутри интервала были переключения,
об этом сообщает пояснение под флажком. Полные значения доступны и в таблице.

После обновления файлов перезапустите процесс Gateway и обновите страницу
через Ctrl+F5. Если работающий сервер отвечает «Неизвестное действие» на запросы
истории, браузер сообщает, что эту версию Gateway нужно перезапустить.
Обновление только страницы не перезагружает код Python в уже работающем процессе.

Поддерживаются параметры Schema типов `number`, `integer` и `boolean`, в том числе
параметры с доступом только для чтения. Сохраняются только принятые текущей Schema
показания устройства и фактические значения из подтверждений команд. Нажатие
переключателя до подтверждения ESP32 само по себе запись не создаёт. Повторное
сообщение состояния после подтверждения не дублирует измерение.

## Настройка записи

По умолчанию история включена, интервал записи — 30 секунд, срок хранения — 30 дней.
Эти настройки общие для Gateway и сохраняются в SQLite. Допустимы интервал
1–3600 секунд и срок 1–365 дней. Выключение записи оставляет уже собранные показания
доступными для графиков до истечения срока хранения.

Числовые параметры записываются не чаще выбранного интервала. Для логических
параметров каждое изменение `false`/`true` сохраняется сразу, а неизменное состояние
записывается с выбранным интервалом. Например, короткое включение LED не потеряется
из-за общего интервала в 30 секунд.

Прошивка может явно управлять историей отдельного параметра:

```json
{
  "parameters": {
    "temperature": {
      "label": "Температура",
      "type": "number",
      "access": "read_only",
      "unit": "°C",
      "history": {"enabled": true, "interval_seconds": 60}
    },
    "enabled": {
      "label": "Питание",
      "type": "boolean",
      "access": "read_write",
      "history": true
    },
    "temporary": {
      "type": "number",
      "access": "read_only",
      "history": false
    }
  },
  "actions": {}
}
```

Отсутствие `history` включает запись для поддерживаемых типов. `history: false`
выключает её для параметра, `true` использует общий интервал. В объекте можно
задать `enabled`, `interval_seconds` или оба поля. Глобальное выключение записи
имеет приоритет над Schema. Строки, перечисления и JSON не записываются;
для них допустимо только явно отключить историю через `false`.

## Хранение и ограничения

Таблица `parameter_history` создаётся автоматически при запуске новой версии.
История входит в стандартные резервные копии SQLite и сохраняется при смене ID
устройства. Восстановление старой резервной копии создаёт отсутствующую таблицу
без необходимости вручную менять базу.

Gateway удаляет просроченные измерения автоматически, в том числе при работе без
браузера. Дополнительно действует общий предел в **250 000 измерений**: при его
достижении удаляются самые старые записи. Поэтому при большом числе датчиков
фактическая глубина истории может быть меньше выбранного срока. Удаление строк
освобождает место внутри SQLite для повторного использования; размер файла на
диске может сразу не уменьшиться.

При смене единиц измерения или типа параметра старые и новые значения не
смешиваются на одном графике. График показывает данные с единицами и типом,
которые объявлены в текущей принятой Schema.

## Запросы протокола

После `browser_hello` Gateway объявляет возможности отдельным сообщением
`gateway_capabilities`: `protocol_version: 1` и список `features`, включающий
`parameter_history`. Это версия браузерного обмена; протокол ESP32 не меняется.
Ошибки неподдерживаемой команды и временной недоступности базы содержат
`action` и `request_id`, чтобы браузер завершил ожидание именно этого запроса.

После обновления Python-файлов нужно перезапустить Gateway. Обновление страницы
через Ctrl+F5 загружает новые файлы интерфейса, но не обновляет уже запущенный
процесс сервера. Если сервер отвечает «Неизвестное действие: get_parameter_history»
или «get_history_settings», он работает на старом коде.

Запрос передаётся как обычное `browser_message`:

```json
{
  "type": "browser_message",
  "action": "get_parameter_history",
  "request_id": "chart-1",
  "device": "esp32-01",
  "parameter": "temperature",
  "range": "day",
  "max_points": 240
}
```

Доступны диапазоны `hour`, `day` и `week`; `max_points` — целое число от 10 до 500.
Ответ `parameter_history` содержит `request_id`, `success`, `device`, `parameter`,
`range`, `unit`, `value_type`, `from`, `to`, `retention_days`, `recording_enabled`
и массив `points`. Каждая точка содержит время `timestamp` в ISO 8601 UTC,
`value`, `min`, `max` и количество исходных измерений `count`.

Числовые точки объединяются по времени с вычислением среднего, минимума и максимума.
Для логических параметров `value` — последнее состояние в интервале (`0`/`1`),
а `min` и `max` позволяют увидеть, что внутри интервала было переключение.
Последнее состояние выбирается по времени измерения; при одинаковом времени
используется более поздняя запись. Перевод часов компьютера назад не подменяет
значение более ранним измерением, записанным в базу позже.
Количество точек ответа ограничено независимо от объёма накопленной истории.

`get_history_settings` возвращает `history_settings`. `set_history_settings`
принимает все три поля `enabled`, `retention_days`, `interval_seconds` и возвращает
`history_settings_result`; новые настройки также рассылаются подключённым браузерам
как `history_settings`. Ответы настроек содержат предел `max_samples`. При ошибке
ответ содержит `success: false` и описание в `message`.
