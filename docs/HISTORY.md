# История показаний и графики

Gateway сохраняет измерения параметров отдельно от журнала событий. Запись идёт
на самом шлюзе, даже если браузер закрыт, с первого принятого показания при
включённой записи. Старые события автоматически не превращаются в измерения.

## Как открыть и читать график

Открой вкладку «Обзор» и выбери устройство с параметром в секции «История
показаний». К этому же графику ведут значок графика справа от параметра
в карточке устройства и значок вверху плитки обзора рядом с ручкой перемещения.
Доступны числовые и логические параметры, для которых Schema разрешает историю.

Синяя линия показывает среднее числовое значение или последнее логическое
состояние в интервале (0 — выключено, 1 — включено). Флажок min/max включает
голубые полосы: минимум и максимум исходных показаний внутри объединённого
интервала. Флажок виден только тогда, когда у отображённых точек min и max
различаются. По умолчанию полосы скрыты; пояснение линии, объединения замеров и
min/max открывается через значок **ⓘ** рядом с «История показаний» при наведении,
фокусе с клавиатуры или нажатии. Точные значения отображённых точек
доступны и в раскрываемой «Таблице показаний» вместе с min/max и числом исходных
замеров. Нажатие на ⓘ закрепляет пояснение; повторное нажатие, нажатие снаружи
или Escape закрывает его. Пустой график не показывает ⓘ.

Нажмите на точку или рядом с линией: маркер и подсказка покажут время и значение
ближайшей точки. Для boolean указаны и `0`/`1`, и Выкл/Вкл. На клавиатуре перейдите
к графику через Tab и выбирайте точки стрелками влево/вправо; Home и End открывают
первую и последнюю. При изменении размера окна или обновлении того же графика
выбор сохраняется по времени; если прежней точки уже нет, выбирается ближайшая.
Показанное время учитывает часовой пояс и язык из настроек интерфейса.

Доступны периоды минута, час, сутки и неделя. До первого ручного выбора для boolean
открывается минута, для `number`/`integer` — час. Выбранный вручную период
запоминается в браузере для следующих графиков, в том числе после перезагрузки.
Выбор min/max также сохраняется локально. Эти предпочтения не меняют запись
на Gateway и независимы у разных origin, например `localhost` и LAN IP.

Минутный период подходит для мигания каждые 500 мс, если устройство передаёт
каждый переход и Gateway успевает его принять. На оси времени минуты показаны
секунды. На больших периодах несколько
переключений могут попасть в одну точку: её значение — последнее состояние,
а min/max показывают, что внутри интервала были оба состояния. Подсказка относится
к точке ответа сервера; она не восстанавливает отдельные измерения внутри интервала.
Для числового среднего время точки — время последнего замера этого интервала,
а не утверждение, что в этот момент устройство передало именно среднее значение.

«Обновить» запрашивает данные вручную. Пока «Обзор» открыт, страница видима и
Gateway подключён, график обновляется автоматически каждые 30 секунд.
При потере связи уже загруженный график остаётся на экране. При смене параметра
или периода прежние точки очищаются, чтобы не показывать их под новым названием.
Если ответ не пришёл за 12 секунд, интерфейс сообщает об ошибке; запрос можно
повторить после проверки связи.

«Скачать CSV» сохраняет точки текущего ответа, включая `min`, `max`, `count`
и единицы измерения. Это те же объединённые данные, что в таблице; экспорт
не выгружает все исходные замеры базы. В CSV время остаётся ISO 8601 UTC,
независимо от часового пояса отображения.

После обновления файлов перезапустите процесс Gateway и обновите страницу
через Ctrl+F5. Если работающий сервер отвечает «Неизвестное действие» на запросы
истории, браузер сообщает, что эту версию Gateway нужно перезапустить.
Обновление только страницы не перезагружает код Python в уже работающем процессе.

Поддерживаются параметры Schema типов `number`, `integer` и `boolean`, в том числе
параметры с доступом только для чтения. Сохраняются только принятые текущей Schema
показания устройства и фактические значения из подтверждений команд. Нажатие
переключателя до подтверждения ESP32 само по себе запись не создаёт. Повторное
сообщение состояния после подтверждения не дублирует измерение.

## Настройка записи

По умолчанию история включена, интервал записи — 30 секунд, срок хранения — 30 дней.
Эти настройки находятся в «Настройки» → «История показаний», общие для Gateway
и сохраняются в SQLite кнопкой «Сохранить». Допустимы интервал 1–3600 секунд
и срок 1–365 дней; `0` не означает безлимитное хранение показаний.
Глобальное выключение записи оставляет уже собранные показания доступными
для графиков до истечения срока хранения. Оно не меняет отдельный журнал событий.

Числовые параметры записываются не чаще выбранного интервала. Для логических
параметров каждое изменение `false`/`true` сохраняется сразу, а неизменное состояние
записывается с выбранным интервалом. Например, короткое включение LED не потеряется
из-за общего интервала в 30 секунд.

Прошивка может явно управлять историей отдельного параметра:

```json
{
  "parameters": {
    "temperature": {
      "label": "Температура",
      "type": "number",
      "access": "read_only",
      "unit": "°C",
      "history": {"enabled": true, "interval_seconds": 60}
    },
    "enabled": {
      "label": "Питание",
      "type": "boolean",
      "access": "read_write",
      "history": true
    },
    "temporary": {
      "type": "number",
      "access": "read_only",
      "history": false
    }
  },
  "actions": {}
}
```

Отсутствие `history` включает запись для поддерживаемых типов. `history: false`
и `history: {"enabled": false}` выключают её для параметра, убирают его из выбора
графиков и скрывают кнопки графика в карточке и плитке обзора, в том числе после
принятия изменённой Schema. Сам параметр, ручное управление им и выбор для плитки
обзора остаются доступны. Уже сохранённые строки остаются в базе до обычной очистки.
При повторном включении истории в Schema они снова доступны, если подходят
по сроку, типу и единицам измерения.
`true` использует общий интервал. В непустом объекте можно задать `enabled`,
`interval_seconds` или оба поля. Глобальное выключение записи
имеет приоритет над Schema. Строки, перечисления и JSON не записываются;
для них допустимо только явно отключить историю через `false`.

Возраст текущего показания отслеживается отдельно от истории и отдельно для
каждого параметра. Пустой heartbeat или изменение другого выхода не обновляют
возраст температуры и не создают для неё новый замер. Последнее известное
значение может оставаться на карточке с пометкой «Устарело» или «Нет свежих
показаний»; это не удаляет уже сохранённые точки. Сам статус подключения не
гарантирует свежесть всех датчиков. [Поведение интерфейса](../web/README.md#где-сохраняются-настройки).

## Состояние выхода и режим работы

Режим «Мигание» описывает алгоритм, а не текущее состояние светодиода. В LED-примере
параметр `led` сохраняет логическое разрешение работы и используется существующими
командами и сценариями. Фактический уровень выхода передаётся отдельно как
`led_output` с подписью «Светодиод»: при рабочем подключении, принятой Schema
и включённой записи включения и выключения, включая поиск устройства,
попадают в историю показаний. Это состояние, которое прошивка подала на GPIO
или адресный индикатор; электрической обратной связи о свете у примера нет.
Во время потери связи прошивка не накапливает очередь переходов: после
восстановления передаёт текущее состояние, без выдуманного заполнения пробела.

У `led` и технических признаков `manual_active`/`blink_active` задано `history:false`.
Поэтому выбор графиков показывает сам светодиод, а не три графика режима/управления.
Старая история `led` не переносится в `led_output`: она содержала другие данные.
После обновления прошивки примите новую Schema в Gateway.

Для `led_output` задано `events:false`: быстрые физические переходы сохраняются
в истории показаний, но не создают отдельную запись журнала событий каждые полсекунды.
Этот общий флаг Schema не отключает передачу состояния и работу автоматизаций.
Сценарий автовыключения, подписанный на `led`, запускается при логическом включении;
каждый импульс `led_output` не перезапускает его таймер.

## Хранение и ограничения

Таблица `parameter_history` создаётся автоматически при запуске новой версии.
История входит в стандартные резервные копии SQLite и сохраняется при смене ID
устройства. Восстановление старой резервной копии создаёт отсутствующую таблицу
без необходимости вручную менять базу.

Gateway удаляет просроченные измерения автоматически, в том числе при работе без
браузера. Дополнительно действует общий предел в **250 000 измерений**: при его
достижении удаляются самые старые записи. Поэтому при большом числе датчиков
или частых переключениях
фактическая глубина истории может быть меньше выбранного срока. Удаление строк
освобождает место внутри SQLite для повторного использования; размер файла на
диске может сразу не уменьшиться.

При смене единиц измерения или типа параметра старые и новые значения не
смешиваются на одном графике. График показывает данные с единицами и типом,
которые объявлены в текущей принятой Schema.

## Запросы протокола

После `browser_hello` Gateway объявляет возможности отдельным сообщением
`gateway_capabilities`: `protocol_version: 1` и список `features`, включающий
`parameter_history`. Это версия браузерного обмена; протокол ESP32 не меняется.
Ошибки неподдерживаемой команды и временной недоступности базы содержат
`action` и `request_id`, чтобы браузер завершил ожидание именно этого запроса.

После обновления Python-файлов нужно перезапустить Gateway. Обновление страницы
через Ctrl+F5 загружает новые файлы интерфейса, но не обновляет уже запущенный
процесс сервера. Если сервер отвечает «Неизвестное действие: get_parameter_history»
или «get_history_settings», он работает на старом коде.

Запрос передаётся как обычное `browser_message`:

```json
{
  "type": "browser_message",
  "action": "get_parameter_history",
  "request_id": "chart-1",
  "device": "esp32-01",
  "parameter": "temperature",
  "range": "day",
  "max_points": 240
}
```

Доступны диапазоны `minute` (60 секунд), `hour`, `day` и `week`;
`max_points` — целое число от 10 до 500.
Ответ `parameter_history` содержит `request_id`, `success`, `device`, `parameter`,
`range`, `unit`, `value_type`, `from`, `to`, `retention_days`, `recording_enabled`
и массив `points`. Каждая точка содержит время `timestamp` в ISO 8601 UTC,
`value`, `min`, `max` и количество исходных измерений `count`.

Числовые точки объединяются по времени с вычислением среднего, минимума и максимума.
Для логических параметров `value` — последнее состояние в интервале (`0`/`1`),
а `min` и `max` позволяют увидеть, что внутри интервала было переключение.
Последнее состояние выбирается по времени измерения; при одинаковом времени
используется более поздняя запись. Перевод часов компьютера назад не подменяет
значение более ранним измерением, записанным в базу позже.
Количество точек ответа ограничено независимо от объёма накопленной истории.

`get_history_settings` возвращает `history_settings`. `set_history_settings`
принимает все три поля `enabled`, `retention_days`, `interval_seconds` и возвращает
`history_settings_result`; новые настройки также рассылаются подключённым браузерам
как `history_settings`. Ответы настроек содержат предел `max_samples`. При ошибке
ответ содержит `success: false` и описание в `message`.
