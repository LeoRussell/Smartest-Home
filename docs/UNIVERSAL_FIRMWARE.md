# Универсальная прошивка ESP32

Универсальный профиль позволяет настроить несколько простых GPIO-компонентов
через Gateway без собственного кода для каждого компонента. Сейчас он
поддерживает цифровой выход, цифровой вход, аналоговый вход ADC и PWM-выход.
Подключение неизвестного датчика само по себе не добавляет драйвер: Gateway
показывает только типы, которые прошивка действительно умеет обрабатывать.

## Подготовка и загрузка

1. Скопируйте `esp32/include/secrets.example.h` в `esp32/include/secrets.h`.
   Укажите Wi-Fi и адрес Gateway. В текущей сети это `192.168.0.102`.
2. В `esp32/universal/include/user_config.h` задайте уникальный
   `UNIVERSAL_DEVICE_ID` каждой плате. Для нескольких устройств используйте,
   например, `esp32-01`, `esp32-02`. Отображаемое имя можно менять отдельно.
3. Подключите ESP32-S3 DevKitC-1 и из корня проекта соберите прошивку:

   ```powershell
   pio run -d esp32/universal
   pio run -d esp32/universal -t upload
   pio device monitor -d esp32/universal
   ```

   Профиль использует общий `GatewayClient` из `esp32/lib` и `secrets.h` из
   `esp32/include`. Существующая прошивка в `esp32/src` остаётся отдельным
   пользовательским профилем.
4. Подключите плату к Gateway и разрешите её подключение в окне запроса.
   Кнопка «Настроить» в карточке устройства появляется для универсального
   профиля.

## Поддерживаемые компоненты

| Драйвер | Что передаёт | GPIO и ограничения |
| --- | --- | --- |
| Цифровой выход | Boolean, доступен командам | HIGH/LOW; активный уровень и начальное состояние настраиваются |
| Цифровой вход | Boolean только для чтения | Подтяжка none/up/down, опрос от 100 мс |
| Аналоговый вход (ADC) | Масштабируемое целое значение, только чтение | ADC GPIO 1, 2, 4–10, опрос от 250 мс; линейная калибровка raw и итогового диапазона |
| PWM-выход | Integer в выбранном диапазоне, доступен командам | Диапазон настраивается внутри 0–255; переключение между ползунком и вводом числа |

Для этого профиля Gateway и прошивка принимают GPIO 1, 2, 4–18 и 21. Они
отклоняют GPIO загрузочных strapping-пинов, USB, flash/PSRAM и GPIO 38/48:
встроенный RGB-индикатор DevKitC-1 использует один из последних пинов в
зависимости от ревизии. Дублировать физический пин между компонентами нельзя.
Проверка не может определить внешние перемычки и подключённые модули, поэтому
перед сохранением сверяйте распиновку именно своей платы.

GPIO ESP32 рассчитаны на логический уровень 3.3 V. Не подключайте к ним
сетевое напряжение, мотор или нагрузку, превышающую возможности вывода:
используйте подходящий драйвер или модуль реле. Для ADC задайте крайние raw
показания и соответствующий им итоговый диапазон. Прошивка линейно преобразует
значение и ограничивает его выбранными границами. Это удобно для простой
калибровки, но не заменяет драйвер конкретного датчика: например, для нелинейного
фоторезистора или датчика температуры нужна отдельная формула/библиотека.

## Настройка и автоматизация

В конструкторе задайте уникальные латинские ID компонента и параметра,
названия, драйвер, GPIO и его настройки. Например:

```json
{
  "format_version": 1,
  "components": [
    {
      "id": "desk_lamp",
      "driver": "gpio_output",
      "label": "Настольная лампа",
      "parameter_id": "enabled",
      "parameter_label": "Включена",
      "pin": 4,
      "active_high": true,
      "initial_value": false
    },
    {
      "id": "light_sensor",
      "driver": "analog_input",
      "label": "Датчик освещения",
      "parameter_id": "light_raw",
      "parameter_label": "Уровень освещения",
      "pin": 5,
      "interval_ms": 1000,
      "unit": "lx",
      "raw_min": 200,
      "raw_max": 3900,
      "value_min": 0,
      "value_max": 1200
    }
  ]
}
```

Gateway проверяет драйверы, IDs, ограничения значений, интервалы, GPIO и
конфликты до сохранения. Названия должны занимать не более 80 байт UTF-8,
единица измерения — не более 24 байт, чтобы гарантированно поместиться в
буферы прошивки. У PWM можно задать допустимые min/max в пределах 0–255 и
начальное значение внутри этого диапазона. Для управляемых выходов настройка
также сохраняет вид элемента отдельно от аппаратной конфигурации; её можно
поменять позднее в карточке устройства. Schema создаётся из аппаратной
конфигурации; те же параметры сразу доступны в карточке устройства и в Blockly. Для изменения
логики сравнения или управления устройством используйте серверные сценарии
автоматизации.

Внизу конструктора можно отдельно назначить индикатор действия «Найти
устройство». Обычный светодиод задаётся GPIO и активным уровнем; встроенный
адресный индикатор ESP32-S3 выбирается как NeoPixel на GPIO 38 или 48 с
настраиваемой яркостью. Выберите фактический пин своей ревизии платы. Этот
индикатор не занимает слот параметра и не становится отдельной LED-командой:
он только добавляет действие `identify` в Schema. Отметка «Считать встроенным
индикатором» отдельно управляет capability `built_in_indicator`. Если индикатор
не выбран, действие не публикуется.

## Применение, сохранение и восстановление

Gateway является основным источником конфигурации и хранит её версию, хэш,
статус и историю в SQLite. JSON-экспорт вместе с принятой Schema записывается
в `gateway/schemas/<ID>.json`; из окна настройки можно скачать JSON. Папку
Gateway браузер напрямую не открывает, поэтому интерфейс показывает путь и
предлагает скачать файл. Импорт сначала проверяется, а затем применяется
только после подтверждения ESP32.

Есть два способа доставить конфигурацию в универсальную прошивку:

1. **Динамический — основной.** Сохраните конфигурацию в Gateway. Он отправит
   её подключённой ESP32; при отключённой плате — при следующем подключении.
   Для обычных изменений повторно собирать и загружать прошивку не нужно.
2. **Встроенный файл — по желанию.** После сохранения нажмите «Файл для
   прошивки (.h)», скопируйте скачанный `device_configuration.generated.h` в
   `esp32/universal/include/` и прошейте плату. При первом запуске без записи в
   NVS прошивка применит этот снимок. Gateway всё равно остаётся основным
   хранилищем и при наличии своей сохранённой конфигурации синхронизирует её с
   устройством. У каждой платы должен быть свой `UNIVERSAL_DEVICE_ID` и свой
   сгенерированный файл.

Перед изменением ESP32 проверяет всю конфигурацию, допустимые GPIO, типы и
уникальность ресурсов, а также SHA-256 конфигурации. При старте та же проверка
сверяет конфигурацию из NVS с сохранённым хэшем. Если проверка не проходит, прежняя конфигурация и GPIO
остаются активны, а Gateway показывает ошибку. При успехе устройство сохраняет
один согласованный пакет версии, хэша и конфигурации в NVS, настраивает пины и
отправляет Schema с подтверждением. После перезапуска Gateway повторно
отправляет сохранённую конфигурацию. Если Gateway DB потеряна, он может
восстановить конфигурацию из разрешённой ESP32 после проверки хэша и Schema.

Состояния датчиков отправляются при изменении и не реже одного раза в 10
секунд. Поддерживаемый список GPIO, ограничения и структура сообщений
определены в `gateway/device_configuration.py` и
`esp32/universal/src/UniversalDevice.cpp`. При добавлении драйвера обновляйте
оба реестра и тесты вместе.

## Ограничения текущего набора

Текущий профиль не реализует произвольные I²C/SPI/UART-датчики, нелинейные
формулы датчиков, интеграцию конкретных модулей, встроенные сценарии самой платы или
автоматическое обнаружение электрических соединений и мигание встроенным
индикатором для команды «Найти устройство». Для этих устройств
добавляется отдельный драйвер в универсальную прошивку. Если требуется свой
алгоритм, действия или режим устройства, используйте пользовательскую
прошивку и протокол из [`ADVANCED_FIRMWARE.md`](ADVANCED_FIRMWARE.md).
