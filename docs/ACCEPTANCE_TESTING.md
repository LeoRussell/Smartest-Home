# Итоговая проверка Smartest-Home вручную

Это план личной приёмки: действия, ожидаемый результат и границы программных
проверок. Галочка означает, что ты сам выполнил пункт на указанной версии.
Наличие автотеста не означает, что пункт уже пройден на твоей плате.

Результаты доступной программной части и наблюдения по C3 записаны отдельно:
[прогон 19.11.2026](ACCEPTANCE_RESULTS_2026-11-19.md).

План охватывает текущие функции. Календарных расписаний, циклов, переменных,
пользовательских аккаунтов и встроенного TLS в проекте сейчас нет.

## Как проходить план

- **Быстрый проход, примерно 30–45 минут активных действий:** START-01–04,
  NET-01–02, CTRL-01–04, CFG-01–03, AUTO-01–05, EVT-01–03.
  Затем отдельно оставить плату на 30–60 минут по STABLE-01.
- **Основная приёмка:** все применимые пункты ниже; ориентир — несколько
  подходов суммарно на 4–6 часов, без сборки нового аппаратного стенда.
- **Длительная проверка:** ещё 24–48 часов с настоящей ESP32.
- Если нет нужной платы, датчика или прошивочного режима, отметь
  **«Не проверено: нет …»**. Проверка в симуляторе не заменяет этот пункт.
- Ошибку записывай по ID пункта: версия, действия, ожидание, фактический
  результат, время, снимок экрана/лог. После исправления повтори пункт и
  соседний основной сценарий.

### Что подготовить

- Компьютер с проектом, Python и PlatformIO; браузер Chrome или Edge.
- Телефон или второй компьютер в той же локальной сети.
- ESP32-C3 SuperMini для универсальной прошивки; прежняя ESP32-S3 с LED на
  GPIO48 пригодится для отдельной проверки пользовательской прошивки.
- Для полного аппаратного прохода: реально подключённые цифровой выход,
  цифровой вход, ADC-источник и PWM-нагрузка либо измеритель. Одной платы с
  индикатором достаточно для основных проверок, но не всех драйверов.
- Скачанная резервная копия рабочей базы и экспорт аппаратной конфигурации.

Для C3 не копируй назначения S3: **GPIO48 на C3 нет**, ADC универсального
профиля C3 поддерживает GPIO **0, 1, 3, 4**. GPIO8 можно явно выбрать для
обычного индикатора поиска; наличие LED и полярность зависят от самой платы.
Фактическую разводку сверяй с платой, а не с названием шаблона в интерфейсе.

## 0. Подготовить отдельную базу для изменений и удаления

Повседневное управление и LAN можно проверить на рабочем экземпляре.
Блокировки, переименование ID, удаление, сокращение истории и восстановление
копий удобнее проходить на отдельной базе. Снимок SQLite не сохраняет
пользовательские предпочтения браузера и содержимое NVS самой ESP32.

1. В рабочем интерфейсе создай и скачай резервную копию. Сохрани отдельно
   JSON аппаратной конфигурации; запиши текущие назначения GPIO.
2. Отключи все реальные платы, которые могут подключаться к этому Gateway,
   включая не участвующие в тесте: копия БД содержит прежние разрешения и
   включённые сценарии. Останови обычный Gateway через Ctrl+C. Дождись завершения:
   копировать работающий файл SQLite вручную не нужно.
3. Из корня проекта выполни в PowerShell:

   ```powershell
   $acceptanceDir = Join-Path $env:TEMP ("smartest-home-acceptance-" + (Get-Date -Format "yyyyMMdd-HHmmss"))
   New-Item -ItemType Directory -Path $acceptanceDir -ErrorAction Stop | Out-Null
   Copy-Item -LiteralPath .\gateway\gateway.db -Destination (Join-Path $acceptanceDir "gateway.db") -ErrorAction Stop
   py run.py --db (Join-Path $acceptanceDir "gateway.db") --http-port 8090 --gateway-port 8765
   ```

   Если рабочая база задана другим путём, копируй именно её вместо
   `gateway/gateway.db`. Новая папка не должна содержать прежний тестовый прогон.
4. Открой `http://localhost:8090` в отдельном профиле браузера или приватном
   окне. Проверь путь БД в выводе запуска. Временно отключи скопированные
   сценарии; затем включи только тестовую плату и нужный сценарий.
   Остальные платы оставь отключёнными на время тестов этого экземпляра.
5. Оставлен порт WebSocket `8765`, поэтому перепрошивать сетевой порт ESP32
   не требуется. Обычный и тестовый Gateway на нём одновременно не запускаются.
   Для параллельного программного экземпляра нужны другие порты и отдельная БД.

Тестовый Gateway по-прежнему может управлять подключённой настоящей платой.
Изменения GPIO сохраняются в её NVS независимо от пути SQLite. После тестов
верни сохранённую аппаратную конфигурацию, останови тестовый экземпляр и
запусти обычный `py run.py`. Проверь восстановленное подключение.

Для проверки восстановления конфигурации **из самой ESP32** используй ещё
один новый путь БД без копирования файла. Этот отдельный тест указан в CFG-10.

## 1. Запуск, остановка и сеть

- [ ] **START-01.** В корне проекта выполнить `py run.py`. Открываются
  `http://localhost:8080` и все разделы; статус Gateway переходит в «На связи».
  Для тестовой базы из раздела 0 адрес страницы — `http://localhost:8090`.
- [ ] **START-02.** Перезапустить Gateway и обновить страницу через Ctrl+F5.
  Нет ошибок запуска/traceback; сохранённые устройства и сценарии остались.
  Обновление страницы само по себе не считается перезапуском Python-сервера.
- [ ] **START-03.** Остановить Gateway через Ctrl+C, затем запустить снова.
  Страница показывает потерю связи и восстанавливает её без повторного ввода
  адреса; порты освобождаются, старые сценарные ожидания не продолжаются.
- [ ] **START-04.** Попробовать второй запуск на уже занятых портах.
  Второй экземпляр сообщает об ошибке; первый продолжает обслуживать страницу
  и плату. После закрытия второго экземпляра первый остаётся доступен.
- [ ] **NET-01.** На телефоне в том же LAN открыть ссылку с IP компьютера,
  которую напечатал запуск, например `http://<IP-компьютера>:8080`.
  Страница и WebSocket работают; `localhost` на телефоне не используется.
- [ ] **NET-02.** Изменить состояние LED с телефона и с компьютера.
  Физический LED и оба интерфейса согласованы; не требуется обновлять страницу.
- [ ] **NET-03.** В настройках браузера задать неверный адрес Gateway.
  Есть понятная ошибка; формы не сообщают об успешном сохранении. Вернуть
  «Автоматически»: соединение восстанавливается с узлом страницы.
- [ ] **NET-04.** Для отдельного программного запуска выбрать другой HTTP-
  и WebSocket-порт. Интерфейс через `run.py` определяет фактический порт;
  явное пользовательское переопределение адреса имеет приоритет.
  Плата подключится туда только при соответствующей настройке своей прошивки.
- [ ] **NET-05.** Проверить доступ после перезапуска компьютера/роутера.
  Если IP изменился, обновить адрес для ESP32 и правила доступа по инструкции
  [LAN_ACCESS.md](LAN_ACCESS.md). Не считать старый IP постоянным.
  Доступность с другого физического устройства проверяется отдельно от localhost.

## 2. Допуск, блокировки и идентификаторы

Все удаления и изменения ID в этом разделе выполняй на тестовой базе.

- [ ] **ACCESS-01.** Подключить неизвестный ID. Появляется запрос с правильными
  ID/именем/прошивкой. До разрешения нет управления и запуска сценариев от платы.
- [ ] **ACCESS-02.** Разрешить без «Запомнить выбор», переподключить плату.
  Подключение работает один раз; следующая попытка снова требует решения.
- [ ] **ACCESS-03.** Отклонить без запоминания и повторить подключение.
  Доступ не предоставлен; следующая попытка снова предлагает выбор.
- [ ] **ACCESS-04.** Разрешить с запоминанием и перезапустить плату/Gateway.
  Повторный допуск происходит автоматически без лишнего запроса.
- [ ] **ACCESS-05.** Отклонить с запоминанием. Плата не получает доступ;
  появляется в свёрнутом списке блокировок. «Снять блокировку» возвращает
  возможность нового запроса; проверить также отмену из события, если она показана.
- [ ] **ACCESS-06.** Нажать «Забыть» и подтвердить. Плата отключается;
  следующая попытка выглядит как новое подключение. Операция не должна
  выдавать себя за удаление всей старой истории из базы.
- [ ] **ID-01.** Через шестерёнку изменить отображаемое имя на «Лампа».
  Имя меняется на карточке; исходный ID прошивки не переписывается.
  Обновить страницу и перезапустить Gateway: имя сохранено.
- [ ] **ID-02.** При подключённой плате проверить ограничение изменения ID;
  имя при этом можно сохранить. Затем отключить плату и задать новый ID Gateway.
  После подключения она связана с прежним устройством, без второй карточки.
- [ ] **ID-03.** Проверить недопустимый ID: кириллица, пробелы, уже занятый
  ID и его вариант с другим регистром. Есть ошибка, прежние данные сохранены.
- [ ] **ID-04.** После допустимого переименования проверить Blockly, группы,
  обзор, историю показаний и соединений: ссылки ведут к тому же устройству.
- [ ] **ID-05.** При наличии двух плат подключить их одновременно с разными
  ID прошивки. Команда одной плате не меняет другую. ID должны быть уникальны
  ещё в прошивках; переименование в Gateway не исправляет два одинаковых hello-ID.

## 3. Карточки устройств и ручное управление

- [ ] **CTRL-01.** Проверить имя, ID, статус, группу, версию прошивки, последнее
  сообщение и актуальность. Число устройств/онлайн согласовано с карточками.
- [ ] **CTRL-02.** Включить и выключить реальный LED 10–20 раз, сначала по одному
  нажатию с ожиданием подтверждения, затем несколько раз быстро. Видимый результат
  совпадает с физическим; нет подвисших кнопок и ложного сообщения об успехе.
  Записать заметную задержку и условия, если управление кажется медленным.
- [ ] **CTRL-03.** Проверить кнопку следующего действия в обзоре: при выключенном
  состоянии предлагается зелёная «Вкл», при включённом — красная «Выкл».
  Подпись текущего состояния при этом остаётся отдельной и правильной.
- [ ] **CTRL-04.** Нажать значок «Найти устройство», если прошивка объявляет эту
  возможность. Мигает физический индикатор. В LED-примере после поиска LED
  возвращается к своему текущему логическому состоянию; в universal отдельный
  индикатор выключается, управляемые выходы не меняются. Обмен и остальное
  управление не замирают на время мигания.
- [ ] **CTRL-05.** Отключить плату и проверить карточку: статус offline,
  показания помечены старыми, управление не обещает выполнение команды.
  После возвращения связи приходит актуальное состояние.
- [ ] **CTRL-06.** У boolean-параметра сменить «Вид» с переключателя на «Список»
  и обратно. Значения берутся из Schema; смена вида сама не посылает команду.
  Вид сохраняется после обновления и виден из другого браузера того же Gateway.
- [ ] **CTRL-07.** При наличии числового выхода проверить слайдер/поле,
  минимум, максимум, шаг и единицу. Недопустимое значение не отправляется;
  отображаемое значение подтверждается устройством.
- [ ] **CTRL-08.** Для авторской Schema проверить enum, строку и действие с
  аргументами. Отображаются только разрешённые варианты и доступные операции;
  read-only параметр нельзя записать. Базовая universal не заменяет такую прошивку.
- [ ] **CTRL-09.** Для прошивки с modes выбрать режим и выполнить объявленные
  операции. Реальный обработчик режима срабатывает; неподдерживаемых операций
  нет. У базовой universal пустой список режимов — ожидаемое поведение.
- [ ] **CTRL-10.** Поиск, онлайн/offline, избранное, сортировка, список/комнаты,
  компактный/подробный вид дают ожидаемые карточки. Сворачивание проводника
  освобождает место; в компактном виде доступны сведения и история соединений.

## 4. Универсальная прошивка и конструктор оборудования

Основной профиль для личной C3 — `esp32-c3-supermini`. Проверки драйверов
выполняй только на соответствующей разводке. Справочник:
[UNIVERSAL_FIRMWARE.md](UNIVERSAL_FIRMWARE.md).

- [ ] **CFG-01.** Устройство показывает правильный профиль платы и кнопку
  «Schema». У новой платы без сохранённой конфигурации пустые компоненты и
  не назначенные прошивкой GPIO корректны; они не должны подбираться автоматически.
- [ ] **CFG-02.** Добавить поддерживаемый компонент из шаблона или вручную:
  ID, имя, драйвер, GPIO, диапазон, единицу, UI. Предпросмотр карточки соответствует
  форме; до применения физический выход не меняется.
- [ ] **CFG-03.** «Сохранить и применить»: различить сохранение Gateway и
  подтверждение ESP32. Успех применения появляется после ACK; карточка и Blockly
  используют подтверждённую Schema, управление работает на указанном GPIO.
- [ ] **CFG-04.** Проверить ошибки: одинаковые ID/занятые GPIO, неподдерживаемый
  пин, неверный диапазон/интервал. Ошибка рядом с полем, рабочая конфигурация
  не заменяется. На C3 ADC5 и S3-пины 38/48 не предлагаются как допустимые.
  Допустимый GPIO0 не отвергается как «пустой». В черновике проверить предел
  компонентов/PWM: не более 8 компонентов и 6 PWM на C3; лишний компонент не
  применяется. Для проверки этих ограничений подключать все выходы не требуется.
- [ ] **CFG-05.** Проверить цифровой выход с правильной полярностью и initial;
  цифровой вход с выбранной подтяжкой. Вход меняется от физического сигнала;
  выход — от команды. Отсутствующий компонент пометить «Не проверено».
- [ ] **CFG-06.** Для ADC подать несколько известных уровней и проверить raw-
  диапазон, преобразованный диапазон, ограничение краёв и единицу. Надпись `°C`
  или `lx` сама не калибрует датчик: отдельно сверить формулу с его характеристикой.
  Для PWM проверить минимум/середину/максимум по измерителю или известной нагрузке.
- [ ] **CFG-07.** Настроить индикатор поиска отдельно от компонентов. Выбрать
  поддерживаемый платой тип/пин и полярность; выполнить CTRL-04. Без индикатора
  поиск не должен притворяться работоспособным. У C3 нет S3 NeoPixel на GPIO48.
- [ ] **CFG-08.** Включить выход, затем «Повторить сохранённую» без изменения
  версии/документа. Нет новой версии и сброса выхода к initial.
  Обычное Wi-Fi-переподключение также сохраняет текущий выход.
- [ ] **CFG-09.** При отключённой плате сохранить изменение. Статус — ожидание,
  а не «Подтверждено ESP32». После подключения документ применяется и получает ACK.
  Перезапуск питания сохраняет конфигурацию NVS; выход принимает заданный initial.
- [ ] **CFG-10.** На отдельной пустой БД разрешить уже настроенную плату.
  Gateway восстанавливает аппаратную конфигурацию из проверенного отчёта ESP32;
  карточка соответствует NVS. Это другой механизм, чем восстановление SQLite.
- [ ] **CFG-11.** Изменить форму, экспортировать JSON, закрыть без применения,
  импортировать файл. Возвращается черновик; импорт сам не включает выходы.
  Неверный JSON/чужой профиль/неподдерживаемый драйвер отклоняется с объяснением.
- [ ] **CFG-12.** Сравнить выгрузки: «Экспорт JSON» — черновик; «Скачать Schema
  из Gateway» — сохранённый аппаратный документ; «Скачать текущую Schema» в
  истории — логическая Schema без GPIO; `.h` — начальная конфигурация для сборки.
  Показанный путь JSON соответствует каталогу рядом с выбранной БД.
- [ ] **CFG-13.** По желанию собрать прошивку с выгруженным `.h` на отдельной
  тестовой плате без прежней записи NVS. Проверить стартовый снимок. При наличии
  NVS приоритет у неё, а сохранённая конфигурация Gateway затем синхронизируется.
  Для обычного изменения GPIO новая прошивка не требуется.
- [ ] **CFG-14.** Начать сохранение и внести новые изменения в форму;
  переключить окно/устройство и открыть снова. Поздний ответ не подменяет новый
  черновик. Возврат к сохранённому документу требует явного действия.
- [ ] **CFG-15.** Для DS18B20 выбрать отдельный драйвер `ds18b20`, фактический
  GPIO4 и трёхпроводное питание с подтяжкой. Проверить дробную температуру °C,
  изменение при нагреве рукой и отсутствие паузы связи на время измерения.
  Отключённый датчик не даёт фиктивных 0/−127; после возвращения появляются
  свежие измерения. Старая ADC/raw-история не смешивается с температурной серией.

## 5. Изменения и история логической Schema

Для смены содержимого hello-Schema нужна тестовая пользовательская прошивка.
Автотесты протокола проверяют этот обмен без перепрошивки реальной платы.

- [ ] **SCHEMA-01.** Изменить параметр Schema, сохранив `schema_version`, и
  подключиться. Gateway всё равно обнаруживает различие и предлагает решение.
- [ ] **SCHEMA-02.** Выбрать «Оставить текущую Schema». Прежняя карточка не
  получает новые возможности; после нового подключения несовпадение предлагается
  снова. Затем принять изменение и проверить новые контролы.
- [ ] **SCHEMA-03.** В истории выбрать сохранённую версию. Скачать текущую
  Schema; файл отражает принятую сейчас Schema, а не любой выделенный снимок.
- [ ] **SCHEMA-04.** При онлайн-плате восстановление для Gateway недоступно.
  При offline восстановить старый снимок на тестовой БД. Меняется представление
  Gateway, но прошивка/GPIO на ESP32 этим действием не перепрограммируются.
- [ ] **SCHEMA-05.** Удалить выбранный снимок: сначала отменить подтверждение,
  затем подтвердить. Удаляется нужная запись; действующая Schema и соседние
  снимки не исчезают. История после перезапуска соответствует удалению.
- [ ] **SCHEMA-06.** Удалить/изменить используемый сценарием параметр или enum-
  вариант. Blockly показывает недоступную ссылку и объясняет ошибку; не подставляет
  другое устройство/значение. Сценарий остаётся доступен для исправления.

## 6. Группы, комнаты и общее выключение

Для полного прохода нужны два устройства с разными способами выключения.

- [ ] **GROUP-01.** Создать две группы, распределить устройства. Название
  группы видно на карточке; список/комнаты, счётчики и фильтр согласованы.
- [ ] **GROUP-02.** Переименовать группу, затем удалить тестовую группу.
  Устройства переходят в «Без группы»; устройства и сценарии не удаляются.
  Перезапуск Gateway сохраняет результат.
- [ ] **GROUP-03.** Через шестерёнку назначить общее выключение: например,
  boolean → false, число → 0, либо объявленное действие с аргументами.
  Проверить все доступные способы на соответствующих Schema. «По прошивке»
  убирает override; «Не участвует» исключает устройство.
- [ ] **GROUP-04.** Включить два устройства и нажать значок питания комнаты.
  Выполняются назначения этой группы, остальные группы не затронуты. Скрыть
  одну карточку поиском и повторить: выключение всё равно относится ко всей группе.
- [ ] **GROUP-05.** Проверить общее выключение всех: результат по устройствам
  показывает успех/пропуск/ошибку. Неназначенный и offline-выход не получает
  отложенную команду при возвращении связи. У «Без группы» нет выключения комнаты.
- [ ] **GROUP-06.** Сменить назначение, сохранить, перезапустить Gateway и
  проверить из другого браузера. Назначение хранится в БД. Новое редактирование
  во время сохранения и черновики соседних групп не теряются от старого ответа.

## 7. Автоматизация: основной проход

Для AUTO-01–05 сначала отключи другие сценарии, управляющие тем же LED.
Времена ниже приблизительные: проверяется полный новый отсчёт без ранней
команды от прежнего запуска, а не точность браузерного таймера до миллисекунды.

- [ ] **AUTO-01.** Собрать «Автовыключение»: изменение LED → фильтр «стало
  равно истина» → подождать 5 секунд → установить LED в ложь. Проверить и
  сохранить включённым. Включить LED: он выключается примерно через 5 секунд;
  история содержит один соответствующий запуск, а не два из ACK и state.
- [ ] **AUTO-02.** Включить LED; через 3 секунды выключить вручную и включить
  снова. Второе включение даёт полные новые 5 секунд. Старое ожидание не
  выключает его через оставшиеся 1–2 секунды.
- [ ] **AUTO-03.** Во время 5-секундной паузы нажать «Остановить»; отдельно
  повторить с отключением сценария и сохранением его изменений.
  Ожидающая команда не выполняется; уже отправленная команда может завершиться.
- [ ] **AUTO-04.** Включить LED и закрыть все страницы браузера. Он всё равно
  выключается через 5 секунд. После открытия виден завершённый запуск.
- [ ] **AUTO-05.** Во время ожидания остановить и запустить Gateway.
  Старый запуск помечается прерванным и не продолжается. Новое подходящее
  изменение запускает новый полный сценарий.
- [ ] **AUTO-06.** Во время запуска проверить шаг, обратный отсчёт и подсветку
  соответствующего сохранённого блока. Перезагрузка страницы восстанавливает
  текущий ход; изменение черновика не подсвечивает чужую версию программы.
- [ ] **AUTO-07.** Создать ручной сценарий с флажком кнопки на устройствах.
  Проверить «Запустить», быстрый сценарий и плитку обзора. Повторное нажатие
  во время исполнения не создаёт второй запуск и не перезапускает ручную паузу.
  Отключённый сценарий не запускается; снятый флажок убирает быструю кнопку.
- [ ] **AUTO-08.** Добавить действие после команды и отключить её целевую плату.
  Ошибка команды останавливает оставшиеся шаги; история объясняет причину.
  После возвращения устройства отменённые шаги не исполняются задним числом.

## 8. Автоматизация: блоки, редактор и симулятор

- [ ] **BLOCK-01.** Быстро переключать категории Blockly, добавлять/соединять
  блоки, менять масштаб, прокручивать страницу к шапке. Категории продолжают
  открываться, меню/блоки не перекрывают шапку вне редактора.
- [ ] **BLOCK-02.** Проверить отмену/возврат, очистку блоков, отмену
  редактирования, копирование сценария. Копия до сохранения — отдельный черновик;
  исходник и его история сохраняются. Очистка редактора не удаляет сценарий.
- [ ] **BLOCK-03.** Оставить свободный блок, второй верхний триггер, пустое
  обязательное поле или неверный тип. Проверка объясняет проблему и не сохраняет
  испорченную программу. Исправление даёт сохранить и снова открыть те же блоки.
- [ ] **BLOCK-04.** Нажать «Проверить» у правильного и неготового сценария.
  Видны проблемы Schema/свежести/доступности; реальных команд и запуска нет.
- [ ] **BLOCK-05.** Запустить «Тестовый запуск» черновика и «Тест» сохранённого
  сценария с виртуальными значениями/подключениями. Видны ветви, команды и
  виртуальное время; физические выходы, события и история запусков не меняются.
- [ ] **BLOCK-06.** В симуляторе пройти обе ветви ЕСЛИ/ИНАЧЕ, сравнения,
  И/ИЛИ/НЕ, чтение параметра/связи, арифметику +/−/×/÷/степень и паузы.
  Типы `true`, `1` и `"1"` не подменяют друг друга; деление на 0 даёт ошибку.
  Действия с аргументами и modes проверить при наличии соответствующей Schema.
- [ ] **BLOCK-07.** По одному проверить триггеры: любое изменение, переход
  к выбранному значению, подключение, отключение, запуск Gateway, ручная кнопка.
  Одинаковый отчёт состояния не является новым изменением. Старт Gateway не
  ждёт подключения всех плат: предусмотреть проверку связи в таком сценарии.
- [ ] **BLOCK-08.** «Без новых изменений» поставить 3 секунды: новое изменение
  в ожидании начинает отсчёт устойчивости заново. Затем отдельно проверить
  «Паузу после запуска»: частые подходящие события не дают частых запусков;
  отключение устройства/сценария отменяет ожидающее срабатывание.
- [ ] **BLOCK-09.** Сохранить/переименовать сценарий, включить/отключить,
  найти поиском и фильтрами, отредактировать и удалить тестовую копию.
  Сообщения о запуске/истории находятся над списком, ошибки формы — у редактора.
- [ ] **BLOCK-10.** Во время сохранения изменить блоки или открыть другую
  программу. Ответ не очищает новый черновик; повторное сохранение после
  неизвестного результата не создаёт лишнюю копию сценария с другим ID.
- [ ] **BLOCK-11.** Изменить блоки, подождать секунду, перезагрузить страницу.
  Предлагается восстановить/удалить локальный черновик. Восстановление не
  сохраняет его в Gateway само; в другой вкладке нет тихой подмены редактора.
- [ ] **BLOCK-12.** Сменить Schema с удалением аргумента/enum или сужением
  диапазона. Старое значение остаётся видимым как ошибочное до исправления;
  явное удаление устаревшего аргумента можно отменить/вернуть в Blockly.
- [ ] **BLOCK-13.** Открыть завершённый запуск, проверить шаги/ошибку, удалить
  одну запись и очистить историю с подтверждением. Активный запуск не исчезает;
  блоки сценария не меняются. Ссылка `>>` ведёт к конкретному связанному запуску.

Для проверки «датчик на одной плате → выход на другой» повтори AUTO-01 с
реальными двумя устройствами и порогом датчика. До появления такого стенда
отметь физическую часть как непроверенную, даже если модель сценария верна.

## 9. Обзор и быстрые сценарии

- [ ] **DASH-01.** В «Настроить» выбрать показание, управляемый параметр,
  действие и ручной сценарий. Иконка/подпись различают типы, текущие значения
  обновляются, переход к устройству открывает нужную карточку.
- [ ] **DASH-02.** Переставить плитки ручкой и кнопками ↑/↓; сохранить и
  перезагрузить. Порядок сохранён. Отменённые изменения состава не применяются;
  предел в 24 плитки соблюдается.
- [ ] **DASH-03.** Проверить график, «Изменить» и «Тест» сценария с плитки.
  Открывается нужный параметр/программа; «Тест» не управляет настоящей платой.
  Последний результат/ошибка и активный ход соответствуют выбранному сценарию.
- [ ] **DASH-04.** На устройствах проверить блок быстрых сценариев: понятны
  имя, связанные устройства, готовность и результат. «Все сценарии» и «Изменить»
  ведут по назначению; ошибка запуска не выглядит как успешное завершение.
- [ ] **DASH-05.** Вернуться в обзор после offline/переименования/смены Schema.
  Старые ссылки отмечены недоступными; другая команда не выбирается автоматически.

## 10. История показаний и графики

- [ ] **HIST-01.** Из карточки и обзора открыть один и тот же параметр.
  Диапазоны минута/час/сутки/неделя, таблица и CSV согласованы по времени/единицам.
  Пустая история объясняется без бесконечного «Загрузка…».
- [ ] **HIST-02.** Включить LED на 2–3 секунды и выключить. Обе смены boolean
  попадают в историю, несмотря на общий интервал 30 секунд. Повтор state после
  ACK не создаёт лишнего такого же измерения.
- [ ] **HIST-03.** Включить/выключить min/max. Голубые полосы появляются только
  при включённом флажке и отражают разброс исходных значений, не вторую команду.
- [ ] **HIST-04.** Сменить интервал записи для числового датчика; выключить
  запись, затем включить. Частота соответствует настройке, старые точки не
  стираются от выключения; работа без открытого браузера продолжает запись.
- [ ] **HIST-05.** На тестовой БД изменить срок хранения показаний и проверить
  сохранение настройки. Для проверки удаления нужны действительно старые точки:
  при их отсутствии отметить очистку как непроверенную, не менять часы ОС.
- [ ] **HIST-06.** Сменить единицу/тип параметра в тестовой Schema. Старые и
  новые несовместимые измерения не смешиваются на текущем графике. После
  отключения платы нет новых нулей, выдаваемых за её реальные измерения.
- [ ] **HIST-07.** При потере Gateway запрос истории заканчивается ошибкой
  и даёт повторить после подключения; нет бесконечного ожидания.
  Неизвестная серверу функция требует перезапуска обновлённого Gateway.
- [ ] **HIST-08.** Нажать на график мышью и на сенсорном экране: подсказка
  показывает значение и время ближайшей точки, остаётся в пределах графика.
  Через Tab и стрелки/Home/End доступны те же точки; ползунка под графиком нет.
- [ ] **HIST-09.** В LED-примере принять новую Schema и выбрать «Светодиод»:
  в списке графиков нет признаков «Ручной»/«Мигание» и командного «Включение».
  На периоде «Минута» мигание показывает чередование 0/1. Выключение, ручной
  режим и поиск правильно отражаются на выходе; импульсы не засоряют журнал.
  Существующее автовыключение по `led` срабатывает через свой срок, без перезапуска
  на каждом импульсе `led_output`. Видимое свечение проверить на самой плате.

## 11. События и уведомления

- [ ] **EVT-01.** Ручная команда видна как результат команды. Затем выполнить
  автосценарий, меняющий LED: успешное автоматическое изменение показывается
  **только как «Изменение состояния»**, без дублирующего «Результата команды».
- [ ] **EVT-02.** Сценарий устанавливает уже имеющееся значение: нового события
  изменения состояния нет. Ошибка команды при этом должна оставаться видимой;
  подробности успешных шагов доступны в истории сценария.
- [ ] **EVT-03.** Фильтр «Изменения состояния» находит автоматическое изменение;
  `>>` открывает правильный запуск. Правило отсутствия дублей проверить также
  в уведомлениях и CSV, включая старые записи, если они есть в тестовой копии.
- [ ] **EVT-04.** Проверить все типы, выбор устройства, поиск по части ID/имени/
  текста и запросу без результатов. «Настройка оборудования» относится к
  сохранению/применению GPIO, а не к обычной команде или принятию логической Schema.
- [ ] **EVT-05.** Подгрузить старые страницы и получить новое событие.
  История не теряется и не дублируется; счётчики найденного, загруженного и
  показанного имеют свой смысл. CSV содержит загруженные строки текущего фильтра;
  для более старой истории сначала нужно догрузить её.
- [ ] **EVT-06.** Считать всё прочитанным: красный счётчик колокольчика исчезает.
  Создать событие — счётчик появляется с количеством; прочитать отдельное,
  затем все. После обновления того же браузера прочитанность сохраняется.
- [ ] **EVT-07.** Из уведомлений открыть подключение, изменение Schema,
  ошибку/сценарий — переход соответствует записи. Проверить «Только важные
  события»: меняется состав уведомлений, а не сам сохранённый журнал.

## 12. Диагностика соединений

- [ ] **CONN-01.** На карточке посмотреть RSSI, uptime, причину запуска и
  последнего разрыва. При выключении питания uptime начинается заново;
  обычное сетевое переподключение не обязано его обнулять.
- [ ] **CONN-02.** Открыть историю значком списка и из шестерёнки.
  Сессия, время последнего сообщения и диагностика относятся к нужной плате.
  Неизмеренный RTT или иной пустой показатель не выдаётся за ноль.
- [ ] **CONN-03.** Подождать больше 15 секунд с открытым окном: свежая страница
  обновляется. Загрузить старые сессии: автообновление приостановлено;
  «Обновить» возвращает к последним. Нет кнопки дальнейшей загрузки без данных.
- [ ] **CONN-04.** Скачать отчёт, также при потере Gateway после загрузки данных.
  JSON открывается и содержит загруженные сессии, до 100, а не обещание всей БД.
- [ ] **CONN-05.** Перезапустить плату, затем отдельно Gateway. Разрывы
  заканчивают прежнюю сессию, повторное подключение открывает новую;
  завершённая история остаётся после перезапуска и переименования ID.
- [ ] **CONN-06.** Сопоставить намеренный разрыв с Serial-логом, RSSI и uptime.
  Причина WebSocket описывает наблюдение Gateway, а не доказывает неисправность
  Wi-Fi. Пустой heartbeat подтверждает связь, но не освежает старое показание датчика.

## 13. Настройки, сохранность данных и резервные копии

RET-01–02 и BACKUP-02–06 — только на отдельной тестовой БД.

- [ ] **SET-01.** Переключить RU/EN, меню сверху/сбоку и часовой пояс.
  Основные страницы, окна, кнопки и даты обновляются согласованно; выбор
  сохраняется в этом браузере после перезагрузки.
- [ ] **SET-02.** Открыть LAN-IP вместо localhost и второй браузер/телефон.
  Предпочтения обзора, языка, избранного и прочитанности могут отличаться:
  они локальны для браузера/origin. Группы, имена, сценарии, GPIO и вид контролов
  приходят из общей БД и совпадают.
- [ ] **SET-03.** Сводка БД показывает размер, записи, устройства, время сессии
  и накопленное время. После перезапуска время сессии новое, накопленное не
  сбрасывается. Число когда-либо подключавшихся не зависит только от старых событий.
- [ ] **RET-01.** Сохранить срок событий `0`, затем допустимое ненулевое
  число. «Сохранено» показано зелёным только после подтверждения и сохраняется
  после перезапуска; недопустимое значение отклоняется.
- [ ] **RET-02.** При наличии событий старше выбранного срока уменьшить его:
  есть подтверждение, удаляются старые события, но не устройства/сценарии/
  снимки Schema. При отсутствии старых строк отметь физическую проверку очистки
  как непроверенную. Размер SQLite не обязан уменьшиться сразу после удаления.
- [ ] **BACKUP-01.** Раскрыть блок копий, обновить список, создать и скачать
  снимок. Список заканчивает загрузку, файл не пустой; сворачивание блока работает.
- [ ] **BACKUP-02.** Создать копию A с тестовой группой/сценарием. Изменить
  их, создать копию B, восстановить A. Вернулось содержимое A; перед восстановлением
  создана страховочная копия, устройства отключаются и могут подключиться снова.
- [ ] **BACKUP-03.** Перед восстановлением запустить сценарий с паузой.
  После восстановления старое ожидание/очередь не выполняет забытые шаги;
  новые события обрабатываются уже восстановленным состоянием Gateway.
  При подключении универсальной платы проверить согласование GPIO и конфигурации.
- [ ] **BACKUP-04.** Во время обновления списка/создания прервать связь браузера
  с Gateway. Есть конечный таймаут и неизвестный результат, кнопки возвращаются;
  нет автоматического повторного создания/восстановления. После подключения
  сначала сверить список. Успех не придумывается по одному истечению времени.
- [ ] **BACKUP-05.** По желанию на тестовой базе создать больше 20 снимков.
  Работает ограничение количества; старейшие вытесняются. Перед этим держать
  нужный контрольный снимок скачанным вне управляемого каталога копий.
- [ ] **BACKUP-06.** На тестовой базе проверить возврат скачанного файла:
  положить его с исходным именем в `backups/` рядом с тестовой БД, обновить список
  и восстановить. Загрузки файла кнопкой из браузера сейчас нет. Повреждённый
  снимок должен отклоняться, сохраняя рабочую БД; такой файл готовить только
  как отдельную испорченную копию, не изменяя контрольный оригинал.

Восстановление SQLite не возвращает прежние `localStorage` браузера и
прошивку платы. Для подробностей — [gateway/README.md](../gateway/README.md).

## 14. Удобство, доступность и разные экраны

- [ ] **UI-01.** На компьютере и телефоне пройти все разделы и основные окна.
  Нет горизонтального выхода обычных форм за экран; заголовки, поля и кнопки
  доступны при прокрутке. Проверить узкий экран около 320/375 px и масштаб 200%.
  Рабочая область Blockly может иметь собственное панорамирование.
- [ ] **UI-02.** Настройки устройства: имя/ID сверху; группа и связь слева,
  общее выключение справа на широком экране; на телефоне блоки последовательно.
  История Schema ниже, кнопки не обрезаны.
- [ ] **UI-03.** В истории соединений пояснение и закрытие помещаются внизу;
  на узком экране могут идти друг под другом. Сохранить/закрыть в конструкторе
  можно без поиска кнопки за краем окна.
- [ ] **UI-04.** Подсказка `i`: наведение, Tab/фокус, клик и тап. Клик закрепляет,
  повторный/снаружи/Escape закрывает. Первый Escape у подсказки сохраняет открытое
  окно и несохранённую форму; длинное пояснение читается без обрезки.
- [ ] **UI-05.** Пройти меню, кнопки, списки, диалоги и уведомления клавиатурой.
  Фокус заметен, Enter/Space действуют по назначению; у кнопок-иконок понятны
  названия. Проверить возврат к управлению после закрытия окна.
- [ ] **UI-06.** Ввести длинные имена и текст с `<`, `>`, `&`, кавычками.
  Текст остаётся текстом, не ломает карточку/подсказку и не превращается в разметку.
  Проверить контраст неактивных/активных/опасных кнопок и сообщений успеха/ошибки.
- [ ] **UI-07.** При редактировании получить новый state/событие/ответ другого
  окна. Поля, фокус и курсор не сбрасываются. Ошибки и ограничения остаются видимыми,
  а дополнительные пояснения доступны через `i`.

## 15. Прошивки и дополнительные способы работы

- [ ] **FW-01.** Собрать нужный профиль universal и отдельно LED-пример.
  Для C3 явно выбран `esp32-c3-supermini`, для S3 — свой профиль. Сборка
  проходит, а загрузчик распознаёт правильный чип. Успешная сборка ещё не проверяет GPIO.
- [ ] **FW-02.** После загрузки проверить Serial: подключение Wi-Fi,
  правильные IP/порт Gateway, hello и допуск. Номер COM узнать заново;
  закрыть Serial Monitor перед upload. На C3 USB может определиться повторно.
- [ ] **FW-03.** На S3 с LED на GPIO48 пройти CTRL-02/04 и AUTO-01/02 с
  LED-примером. Его собственная Schema, UI по умолчанию и обработчики работают
  без универсального конструктора. На C3 этот тест не подменяется S3-прошивкой.
- [ ] **FW-04.** Если используешь собственные modes/actions, проверить каждый
  обработчик, аргументы, отчёт state и ошибку неподдерживаемой команды по
  [ADVANCED_FIRMWARE.md](ADVANCED_FIRMWARE.md). Будущий авторский код не покрывается
  автоматически проверками текущего LED-примера.
- [ ] **CLI-01.** Если нужна консоль: остановить `run.py`, в отдельном окне
  PowerShell задать путь тестовой БД через `GATEWAY_DB_PATH` и запустить
  `.\.venv\Scripts\python.exe gateway\main.py` из корня проекта.
  Проверить `devices`, `status`, `use <id>`, `schema`, `events`, `history`.
  `set` и `call` на безопасном LED используют те же проверки/ACK; `exit` завершает
  Gateway. Этот запуск не раздаёт веб-страницу. Закрыть отдельное окно PowerShell
  после теста, чтобы его `GATEWAY_DB_PATH` не подменил БД при обычном запуске
  из исходного окна.

Если PowerShell не знает команду `pio`, используй полный путь. Эти команды
**только собирают**, не загружают код и не меняют плату:

```powershell
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -d esp32/universal -e esp32-c3-supermini
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -d esp32/universal -e esp32-s3-devkitc-1
& "$env:USERPROFILE\.platformio\penv\Scripts\pio.exe" run -d esp32/examples/led
```

Порядок загрузки и выбор других S3-профилей — в [esp32/README.md](../esp32/README.md).
Не меняй ID в прошивке и не стирай NVS ради обычного переименования карточки:
для этого есть ID Gateway. Смена исходной идентичности — отдельная операция.

## 16. Переподключения и длительная работа на настоящей плате

- [ ] **STABLE-01.** Оставить плату на 30–60 минут, иногда управлять LED.
  Нет самопроизвольных пар отключение/подключение, зависших команд и роста
  задержки. При разрыве сохранить время, Serial-лог и отчёт истории соединений.
- [ ] **STABLE-02.** Отдельно проверить перезапуск питания платы, временную
  потерю её Wi-Fi и перезапуск Gateway. Связь возвращается; причины и сессии
  согласованы. Wi-Fi-тест затронет телефон/ПК, если выключить общий роутер:
  запланировать его отдельно. Не удалять пароль сети/конфигурацию ради разрыва.
- [ ] **STABLE-03.** После возврата связи нет дублирующего физического действия,
  ожившей bulk-команды или старой паузы. Проверить на безопасном LED; обычное
  новое нажатие после подключения снова работает.
- [ ] **STABLE-04.** Оставить стенд на 24–48 часов. Первую часть держать браузер
  открытым, затем закрыть его и снова открыть. Gateway-компьютер не должен спать.
  Записать начало/конец, RSSI/uptime, неожиданные разрывы, ошибки сценариев и
  память процесса в начале/конце при сопоставимой нагрузке. При подозрении на рост
  памяти добавить промежуточные наблюдения; одна пара значений не доказывает утечку.
- [ ] **STABLE-05.** В конце физического прогона повторить ручное управление,
  поиск, автовыключение, график и создание копии. Нет накапливающегося ухудшения;
  причина каждого неожиданного разрыва либо установлена, либо записана как
  нерешённая, даже если устройство быстро вернулось.

Потерю конкретного ACK, повтор одного `command_id`, сбой записи NVS между
исполнением и подтверждением обычными кнопками надёжно не воспроизвести.
Это отдельный протокольный/аппаратный стенд, а не просьба быстро нажимать кнопку
или выдёргивать питание наугад. При утраченном результате в кэше допустима
явная ошибка/неизвестный результат; недопустимо повторное физическое действие
под видом гарантированного восстановления. Это не обещание «ровно один раз»
для любой будущей прошивки и любого отказа питания.

Невалидные служебные сообщения, неверный хэш конфигурации, искусственно
задержанные ответы, частичная телеметрия и точный момент потери ACK покрываются
программными тестами. Если воспроизвести их из обычного интерфейса не удалось,
не отмечай их как физически проверенные. Отключение сети браузера проверяет
обрыв браузер ↔ Gateway, а не обрыв ESP32 ↔ Gateway.

## 17. Что можно проверить автоматически

Эти проверки можно поручить Codex или выполнить самостоятельно. Они используют
временные базы/виртуальные сообщения и не подтверждают физическую разводку.
Результаты каждого запуска фиксируются отдельно; этот список команд сам по
себе не означает завершённую ручную или аппаратную приёмку.

| Проверка | Что она подтверждает | Что остаётся проверить лично |
| --- | --- | --- |
| Python `unittest` | Schema, допуск, типы, SQLite, группы, команды, ACK/повторы, сценарии, история, backup/restore, запуск/остановка | Поведение конкретной собранной системы с твоими данными и платой |
| Браузерный smoke с подменённым WebSocket | Действия и ошибки UI, черновики, подсказки, раскладки RU/EN и 320/375/1440 px | Реальные тапы/клавиатура, удобство и контраст на экране, настоящий обмен с ESP32 |
| PlatformIO build | Сборка выбранных прошивок для соответствующих чипов | Загрузка, старт, USB, GPIO, электрическая полярность, Wi-Fi и питание |
| Native C++-тесты | Логика кэша команд/NVS-адаптера и ограничений платы/PWM | Настоящая flash и обрыв питания в конкретный момент |
| Программный soak | Настоящий Gateway и WebSocket с имитаторами: таймауты, потерянные/повторные ACK, reconnect/restart | Радиоканал, DHCP/роутер/firewall и 24–48 часов физического стенда |

Из корня проекта после создания `.venv` обычным запуском:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s gateway -p "test_*.py"
.\.venv\Scripts\python.exe -X utf8 web\tests\browser_smoke.py
.\.venv\Scripts\python.exe -X utf8 gateway\soak_test.py --duration 180 --interval 0.25 --restart-every 100 --report "$env:TEMP\gateway-acceptance-soak.json"
```

Каждую команду выполняй отдельно и сохраняй её итог. Для браузерной проверки
нужен Chrome/Chromium/Edge. Native-тестам нужен C++-компилятор и, для адаптера,
ArduinoJson: строки `skipped` означают пропуск, а не успешную проверку. Подготовка
описана в [README](../README.md#проверки). Длительность 180 секунд не гарантирует
достижение порога в 100 циклов: фактические счётчики и перезапуски смотри в отчёте.

Для программного суточного прогона есть [SOAK_TEST.md](SOAK_TEST.md). Его результат
записывается отдельно от STABLE-04 с физической ESP32. При получении нового
результата сравнивай версию кода, профиль и реально загруженную прошивку.

## Когда можно считать личную приёмку законченной

1. Пройдены применимые основные функции, включая физическое управление,
   повторный 5-секундный отсчёт, LAN со второго устройства и восстановление копии.
2. Нет потери конфигурации/черновиков, ложного успеха, двойных действий и
   возобновления отменённых сценарных шагов после переподключения.
3. Программные проверки завершились без ошибок; все пропуски объяснены.
4. Физический длительный прогон завершён; неожиданные разрывы разобраны.
5. По неподключённым датчикам, отсутствующим платам и авторским режимам есть
   явный список «Не проверено». Итог относится к проверенному составу стенда.
6. Рабочая конфигурация платы возвращена, тестовый Gateway остановлен,
   обычный `py run.py` запускается и управляет устройствами.

Для возврата ошибки достаточно такого сообщения:

```text
Пункт: AUTO-02
Версия проекта / прошивки:
Плата и GPIO:
Шаги и точное время:
Ожидал:
Получил:
Повторяется: каждый раз / иногда (сколько раз из скольких)
Лог/скриншот/отчёт:
```
