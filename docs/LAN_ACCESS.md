# Доступ к интерфейсу из локальной сети

Gateway работает на одном компьютере. Другие компьютеры и телефоны открывают
его интерфейс в браузере; устанавливать на них Python или копировать проект
не требуется. Компьютер может быть подключён кабелем, а телефон — к Wi-Fi
того же роутера, если устройства находятся в одной локальной сети.

## Запуск и адрес

Сначала создай `.venv` и установи зависимости по [README](../README.md#запуск-gateway).
Для последующих запусков из корня проекта достаточно:

```powershell
py run.py
```

В терминале появятся ссылки:

```text
Web interface: http://localhost:8080
Gateway: ws://localhost:8765
Local network: http://192.168.0.104:8080
```

На другом устройстве открывай ссылку `Local network`. IP в примере условный:
используй адрес из своего терминала. Если обнаружено несколько адресов,
выбирай адрес компьютера в общей с телефоном сети.
`localhost` и `127.0.0.1` на телефоне указывают на телефон, а `0.0.0.0` является
адресом прослушивания сервера, а не ссылкой для браузера.

По умолчанию `run.py` принимает подключения на всех IPv4-интерфейсах. Если
ранее было задано `GATEWAY_HOST=127.0.0.1`, явно укажи:

```powershell
py run.py --host 0.0.0.0
```

Браузер использует имя/IP открытой страницы и автоматически получает порт
Gateway из `/gateway-config.js`. Ответ не кэшируется и не содержит паролей,
адресов ESP32 или данных базы. Нестандартные порты тоже поддерживаются:

```powershell
py run.py --http-port 8090 --gateway-port 8777
```

В этом случае открывается `http://<IP>:8090`, WebSocket использует `8777`.
Явно сохранённый адрес в «Настройки» → «Подключение к Gateway» имеет приоритет.
Кнопка «Автоматически» возвращает адрес узла страницы и порт запуска.
Адреса `ws://0.0.0.0:8765` и `ws://[::]:8765` для подключения не принимаются:
это адреса прослушивания сервера. Ранее сохранённый такой адрес автоматически
сбрасывается. Если сама страница открыта через `0.0.0.0` или `[::]`,
автоматическое подключение использует соответственно `localhost` или `[::1]`.
Явно сохранённый корректный IP имеет приоритет и сохраняется при обрывах связи.
Если WebSocket не открылся за 10 секунд, интерфейс показывает ошибку с адресом
попытки и автоматическим адресом. Повторные попытки используют прежний выбранный
IP; автоматически подменять его другим компьютером интерфейс не будет.
При отдельном `python -m http.server` автоматический порт Gateway — `8765`.
Настройки соединения, языка и прочих предпочтений независимы для каждого
браузера и адреса сайта.

У ESP32 свой адрес подключения: IP берётся из `GATEWAY_IP` в
`esp32/shared/include/secrets.h`, порт — из `GATEWAY_PORT` соответствующей
прошивки. Изменение адреса в браузере не меняет эти значения на плате.
При изменении DHCP-адреса компьютера обнови сетевую настройку ESP32 и загрузи
нужный проект/профиль; аппаратные настройки универсальной платы в NVS при обычной
загрузке сохраняются. Закреплённый адрес компьютера в настройках DHCP роутера
позволяет реже менять адрес в прошивках.

## Windows Firewall

Для доступа нужны входящие TCP-подключения к двум портам: `8080` для страницы
и `8765` для Gateway и скачивания резервных копий/Schema. Одна доступная
страница ещё не подтверждает доступность второго порта.

В проекте есть скрипт, который создаёт разрешение для текущего Python,
выбранного сетевого адаптера, его IPv4-адреса и локальной подсети. Открой
PowerShell **от имени администратора**, перейди в каталог проекта и сначала
просмотри план:

```powershell
cd C:\Smartest-Home
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\enable-lan-access.ps1 -InterfaceAlias "Ethernet" -WhatIf
```

Вместо `Ethernet` можно указать имя своего подключённого адаптера, например
`Wi-Fi`. При единственном подходящем адаптере параметр можно опустить.
`-WhatIf` выводит план без изменений. Для применения повтори команду без него:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\enable-lan-access.ps1 -InterfaceAlias "Ethernet"
```

Скрипт добавляет собственное правило и не меняет существующие правила Python,
UDP-правила, профиль сети или состояние брандмауэра. Если найдено явное
блокирующее правило для этого Python, настройка останавливается: такое правило
нужно отдельно проверить, поскольку запрет имеет приоритет над разрешением.
`ExecutionPolicy Bypass` относится только к этому процессу PowerShell.
Параметры адресов, портов, программы и пользователя описаны в
[документации Windows Firewall](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule).

Для нестандартных портов передай те же значения, что и в `run.py`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\enable-lan-access.ps1 -HttpPort 8090 -GatewayPort 8777
```

Машинные параметры настройки сохраняются в `deploy/.lan-firewall-state.json`.
Этот файл исключён из Git. Для удаления созданного правила:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\enable-lan-access.ps1 -Remove
```

Если IP, адаптер, Python или порты изменились, сначала выполни `-Remove`, затем
создай правило заново. Сохрани файл состояния до удаления конфигурации;
повторная настройка поверх существующего состояния намеренно отклоняется.

## Если не подключается

| Признак | Что проверить |
| --- | --- |
| Страница не открывается | `run.py` работает; указан текущий LAN IP компьютера и HTTP-порт; компьютер и телефон находятся в одной сети; входящий TCP-порт разрешён |
| Страница открылась, Gateway недоступен | Разрешён второй TCP-порт; в настройках браузера не остался другой адрес; нажми «Автоматически» |
| На обычном Wi-Fi работает, на гостевом нет | Гостевая сеть или изоляция клиентов роутера может запрещать доступ к компьютерам LAN |
| После смены IP пропала связь | Возьми новую ссылку из терминала и пересоздай правила доступа; IP в прошивке ESP32 настраивается отдельно |
| При `--host 127.0.0.1` работает только на компьютере | Используй `--host 0.0.0.0` |

Для постоянной работы компьютер с Gateway должен оставаться включённым,
а процесс `run.py` — работать. В Linux разреши соответствующие TCP-порты
в используемом брандмауэре для своей локальной подсети.
